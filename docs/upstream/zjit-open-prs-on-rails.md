# Open ZJIT PRs on Rails (bet Z4)

Three open ZJIT PRs, each tested alone and all three together on current ruby/ruby master, on Rails
workloads, against master with an A/A control:

* [ruby/ruby#18326](https://github.com/ruby/ruby/pull/18326) (nozomemein, draft, head `fec845b8d7`):
  monomorphic `sendforward`, i.e. call sites that pass `...` (every Rails `delegate` method).
* [ruby/ruby#19583](https://github.com/ruby/ruby/pull/19583) (tekknolagi, draft, head `9dd8e0f6f6`):
  `recv.send(:name, ...)` with a constant Symbol.
* [ruby/ruby#19483](https://github.com/ruby/ruby/pull/19483) (ours, head `70a47d2cad`): protected sends
  guarded by the runtime caller `self`.

Nothing was posted. The draft comments at the end are for Thomas to check and post.

**#18326 has a correctness bug.** It specializes on the profiled *caller* call info but guards only the block
handler at run time. When a later caller passes a different argument count or a splat, the forwarded
arguments are read from the wrong stack slots. Default `--zjit`:

```ruby
def target(*args) = args
def fwd(...) = target(...)

100.times { fwd(1) }
p fwd(1, 2)     # master [1, 2]   #18326 [2]
p fwd           # master []       #18326 [main]   (a stale stack slot)
p fwd(*[[:a]])  # master [[:a]]   #18326 [[[:a]]]
```

The original PR build at its own base (`fec845b8d7`) gives the same results. The same root cause is behind the
three `bootstraptest/test_method.rb` failures (lines 1266, 1272 and 1317) in the PR's own
`btest --zjit-call-threshold=2` CI jobs, which have been red since 2026-08-13 without a comment. On Rails it
breaks `HashWithIndifferentAccess#merge(...) = dup.update(...)` when called as `merge(*hashes)`,
`ThroughReflection#scope_for` (generated by `delegate`), `MiddlewareStack::Proxy#use(...)` and
`query_value(...) = single_value_from_rows(query_rows(...))`.

Two master bugs turned up on the way. Neither involves any of the PRs (see [Master bugs](#master-bugs)):
a ZJIT miscompile at `--zjit-call-threshold=1` (a local reads `nil` after an inlined call with a block,
fixed by open #18960), and an interpreter `[BUG]` when a Ractor reads a frozen `Set` class ivar (Bug #22419,
from #19145, draft fix #19447).

## Master bugs

Neither involves the three PRs. Both reproduce on master `90dbced795`. Both are already known and have open fixes,
so nothing new is filed.

**ZJIT: local reads `nil` after an inlined call with a block that writes it** (`--zjit-call-threshold=1` only):

```ruby
class NilClass
  def m(&) = nil
end

def t
  x = 1
  nil.m { x = 2 }   # block never runs
  x
end

p 100.times.map { t }.tally  # interpreter, YJIT, --zjit: {1 => 100}; --zjit-call-threshold=1: {nil => 100}
```

It needs a receiver of statically known class (`nil`, `true`, `1`, `"s"`; not `Object.new`), a callee with a
block parameter (`&`, `&b`, `...`), and a block that assigns the outer local. The optimized HIR inlines `m`,
never stores `x = 1` to the frame, and then reloads `x` from the frame (`LoadField v20, :x@-0x20`) because the
block may write it, so it reads a stale `nil`. That is Rails' `ObjectTryTest#test_try_only_block_nil`
(`NilClass#try(*, &)`). Thresholds 2 and default are correct.

This is the known [Shopify/ruby#976](https://github.com/Shopify/ruby/issues/976). Open
[ruby/ruby#18960](https://github.com/ruby/ruby/pull/18960) ("ZJIT: Locals in stack map; HIR local spills;
always locals in exits", head `0564799aa1`) fixes it. Merged onto master (only `zjit/src/hir/opt_tests.rs`
conflicts, master's version kept), the repro gives `{1 => 100}` at thresholds 1 and 2 and default, and a
32-case matrix (8 block-parameter signatures × receivers `nil`, `true`, `1`, `Object.new`) has 0 divergences,
against 15 on master.

**Interpreter: `[BUG]` when a Ractor reads a frozen `Set` class ivar** (no JIT):

```ruby
class C; @s = %w[a b].to_set.freeze; class << self; attr_reader :s; end; end
p Ractor.new { C.s }.value
# [BUG] rb_objspace_reachable_objects_from_local: set is owned by another Ractor
```

This aborts Rails' Action Pack suite at `ControllerInstanceTests#test_action_methods_is_ractor_safe_by_default`
(`AbstractController::Base.action_methods` memoizes a frozen `Set`).

Bisected with `miniruby`: [`e8964f3aa3`](https://github.com/ruby/ruby/commit/e8964f3aa3) is good and its child
[`f0439cdfa7`](https://github.com/ruby/ruby/commit/f0439cdfa7) "Remove VM lock from Ractor.make_shareable()"
([ruby/ruby#19145](https://github.com/ruby/ruby/pull/19145), merged 2026-10-06) is the first bad commit. Master
`0c404b09a0` (2026-11-03) still crashes. It is already reported as
[Bug #22419](https://bugs.ruby-lang.org/issues/22419) (yahonda, 2026-10-08, from Rails nightly CI, same
bisect, assigned to the ractor group; #22497 was closed as its duplicate). ko1's draft fix
[ruby/ruby#19447](https://github.com/ruby/ruby/pull/19447) "Only the owner Ractor makes its objects shareable"
(head `8ef1b2c0e5`, two open review comments from jhawthorn) merges cleanly onto master. With it, both repros
pass, the Rails test passes, the full Action Pack suite with its Ractor tests passes (4,745 runs, 0 failures,
0 errors), and `test/ruby/test_ractor.rb` passes (86 tests).

## Method

The probe is [`zjit_open_prs_probe.rb`](../../bench/upstream/zjit_open_prs_probe.rb) (`ruby probe.rb` against
`ruby --zjit --zjit-call-threshold=N probe.rb`, diffed). The ruby-bench counter harness writes
`RubyVM::ZJIT.stats` after 10 warmups and 3 iterations. Callgrind uses the irwin window (`--dump-before=vm_stat`,
10 warmups, 3 measured iterations with GC disabled) under `--zjit`. The Rails suites ran in one copy of Rails per
build, with `PARALLEL_WORKERS=1` and per-test verbose output diffed by test name. Anonymous class names are
normalized, and tests named `ractor_safe` are excluded on every build.
