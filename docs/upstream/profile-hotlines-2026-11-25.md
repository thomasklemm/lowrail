# Profile hot lines across 12 apps (2026-11-25)

Generated by [script/profile-hotlines](../../script/profile-hotlines):

```sh
script/profile-hotlines --check 30 --not-lead 'prosopite=test-only N+1 detection' @bench/upstream/profile_hotlines/apps.txt
```

Score: a line's share of the app's request objects (job objects for an app without requests), averaged over all 12 apps, so (apps with the line / 12) × (mean share where it runs). Reach: the share of the app's requests that run the line. App code, Ruby's stdlib and default gems and dev/test-only work are left out. Rows merge the same file, method and source text across gem versions. Links point at the tag of the newest released version an app runs.

## Reading (by hand, after the run)

Everything below this section is the script's output. This section is the judgment on it, and where the two differ
(rack below), this section is the later check.

* **The ranking reproduces the sweep.** On the sweep's five apps that serve requests,
  `script/profile-hotlines --check 0 --top 12 --out - @bench/upstream/profile_hotlines/sweep5.txt` lists the sweep's
  ranks 1–12 in the same order: rqrcode_core `rszf` 4.99% (sweep 5.00%), prosopite 1.61% (1.65%), cancancan `can`
  0.53% (0.53%), then rgeo `to_wkt` twice, `tag_option`, `html_safe`, `from_database`, `merge`, `broadcast_logger`,
  `Arel::Table#[]` and `get_oid_type`. The small gaps come from Dawarich's `r2` and OSM's serial `s1` captures, which
  replace the sweep's `base`. Across all 12 apps, RQ1's line stays first (2.19%). CC1's line drops to #22 (0.24%),
  because Rails lines reach every app and Huginn's jobs lift Hashie. Both lines show as ours: RQ1 is draft
  whomwah/rqrcode_core#57, CC1 is draft CanCanCommunity/cancancan#941.
* **Leads, best first:**
  1. **hashie `Mash#respond_to_missing?`** (#3 and #5). `method_suffix` converts the Symbol with `to_s` on every
     `respond_to?`, and `log_collision?` makes that call on every key write. That is 6.2% of Huginn's job objects,
     0.9% of Forem's requests at 95% reach and 0.4% of CodeTriage's at 100%. The code is unchanged in 6.0.0 and on
     master, and no PR or issue names either method. 6.0.0 came out on 2026-11-11 (dblock, the last human commit),
     and 5.2.0 took the similar `convert_key` fix (`Symbol#name`). This is the best lead.
  2. **rack `Request#split_header`** (#27). `value.strip.split(/[, \t]+/)` runs for every `host`, `port`, `scheme` and
     `ip` read through a forwarded header or `REMOTE_ADDR`, usually on a single value. It is in 9 of 12 apps,
     Campfire 1.74% (49% from its `request.base_url` per importmap entry) and Pingcrm 0.29%. No PR from others names
     it. The script marks it "ours in repo" because RACK2550 and RK3 are open there. jeremyevans approved RACK2550 on
     2026-11-04, so only RK3 is unanswered and rack has room under the gem cap of 2.
  3. **concurrent-ruby `NonConcurrentMapBackend#dupped_backend`** (#93). `each_pair` copies the whole Hash before it
     iterates. The line is in all 12 apps but small (0.11%); its largest share is Forem at 131 objects per request,
     99% of them from its `restore_original_host` middleware. The copy is deliberate, so that iteration survives
     writes. Check first whether the callers are `keys`/`values`, which could read `@backend` directly. No PR names
     the file.
  4. **rgeo `CoordSys::CS` `to_wkt`** (#31). Building a WKT string allocates about 31,700 objects per request that
     runs it, but only in Dawarich and only on 3% of its requests (demo-data seeding and the track serializer). The
     line is unowned, and the last maintainer commit was 2026-04-16. Worth it only if Dawarich's track serializer
     matters.
  5. **typeid `UUID#string`** (#50), weaker. It is 86 objects on every Lobsters request, from its `x_request_token`
     initializer. The gem's last release (0.2.2) and its last commit are both from April 2024.
* **Unowned but not leads:** prosopite runs in test only. csv `parse_quotable_loose` (#46) is a `split` per line in
  Huginn's CSV agent, on 1% of its jobs. The Rails rows #7, #11, #21, #23 and #30
  (`from_database`, `Arel::Table#[]`, `initialize_copy`, `convert_dot_notation_to_hash`, `extract_attributes`) each
  allocate one object per operation. They are already in the census data, and rails/rails opens only urgent fixes.
* **Owned or changed upstream:** Rails `get_oid_type`, `tag_option`, `broadcast_logger`, `build_handle` and
  `references` have changed on main but not in a release. sqlite3 `get_metadata` is gone in 2.10.2, and json's `parse`
  line changed in 3.2.0, so for those apps the fix is an upgrade.
* **Reading the Owner cell:** for Rails rows with a common method name, "open PR #N" only means an open PR changes
  that file. For example, #48284 (`invert_where`) changes `where_clause.rb`. Read the PR before you count it as
  ownership.
