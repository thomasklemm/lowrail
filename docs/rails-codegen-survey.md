# Rails runtime code generation: prefer measured programs to blanket rewrites

2026-10-21. **No qualifying upstream patch in this batch.** No Rails production
change, fork push, upstream PR/comment/issue, support claim or whole-request
speed claim. This is a source inventory, untimed reachability recount and
rejected microbenchmark experiments. Full component suites and Thermos were
not run for candidates that failed the performance/reachability gate.

## What #59250 actually does

`CodeGenerator.batch` amortizes eval; `define_cached_method` shares one compiled
method body under a **namespace + canonical name**, then installs an
`UnboundMethod` under the public name. That final `define_method` is **not a
bmethod**: copying an ordinary def does not turn its ISeq into a block.
Enum names and supported literal values go into the generated source; values
without safe literals retain the original closure fallback. It removes both
closure dispatch and public-send work, not just a different spelling of the
same generic interpreter operation.

Four constraints matter when repeating this pattern:

1. The cache key must distinguish every different body, not every model.
   Different public aliases may share a body; different dispatch targets may
   not. See [#42095](https://github.com/rails/rails/pull/42095), the wrong-target
   alias regression [#45416](https://github.com/rails/rails/issues/45416), and
   namespace/sharing fixes [#52117](https://github.com/rails/rails/pull/52117)
   / [#52118](https://github.com/rails/rails/pull/52118) after
   [#52111](https://github.com/rails/rails/issues/52111).
2. A captured mutable value, Proc, route set or defining class is not a Ruby
   literal. Moving it to a new ivar/constant requires a separate lifetime,
   inheritance, duplication, redraw and Ractor argument.
3. Preserve `public_send` versus `send`, argument/keyword/block forwarding,
   visibility, `super`, error behavior and callbacks. A direct call that can
   now reach a private method is not a free optimization.
4. Source locations and eval batching are observable tooling contracts.
   Action View intentionally batches **without** global method caching:
   [#52470](https://github.com/rails/rails/pull/52470),
   [#52810](https://github.com/rails/rails/pull/52810). Sharing every method
   globally is not an improvement.

## Inventory and verdicts

Scope: all **1,530** first-party Ruby files under component `lib/` and `app/`,
excluding generator `templates/`. Includes shipped testing/CLI helpers,
explicitly separated below. Zero Prism parse errors. The index contains
**307 emitter/eval/exec API calls**, **77 method_missing/respond_to_missing?
def declarations**, **383 direct send/public_send/__send__ calls**, and **1,097
native/internal attribute and alias_method API calls**. These populations overlap by enclosing
source; do not add them to get a number of generated methods. Dynamic source
strings and arbitrary user code are not recursively executed by this scan.
The index follows emitter implementations, not every application of DSL
macros such as `belongs_to` or `class_attribute`; Ruby `alias` keyword syntax
is outside the counted API-call population.

The following tables give the body form and verdict for the indexed sites.
Paths omit the component's `lib/<component>/` prefix where unambiguous; the
appendix has full canonical links and every line. **Already optimized** means
already an ordinary/native method, not proof that its entire algorithm is
optimal. **Candidate** means unmeasured follow-up, not a ready PR. **Semantics
bound** means impossible to replace with literal-only code while retaining
the general API; it does not rule out a more complex reference-holder design.

### Eval/exec and missing-method paths are not all emitters

- The appendix's `instance_exec`, `instance_eval`, `class_exec`, `module_exec`
  and block-form class/module eval entries are indexed even when they only
  **execute** a callback or DSL. Mail defaults, cache-key procs, browser/rate/
  policy callbacks, association/default/named scopes, validations, token
  payloads, job queue/priority callbacks, rescue handlers and load hooks
  execute arbitrary user code. Verdict: semantics bound for literal-only
  replacement; no generated-method optimization is implied by that API name.
- Block-form evals used by inheritance hooks, Concern, configurable/naming/
  model-schema setup, engine isolation, template-inline mixins, Rails paths
  and railtie configuration define ordinary Ruby defs/attributes or run setup.
  Verdict: already ordinary defs or not worth a request-throughput change.
  They are not bmethods just because the enclosing DSL used a block.
- The 77 missing-dispatch definitions fall into lazy generators (AR dynamic
  matchers/relation delegation and AM attributes/acceptance, above) or genuine
  open-ended proxies: mailers/parameterized mailers, MIME collectors/type
  helpers, routes proxies/lazy route sets, Atom/tag builders, schematized JSON,
  connection/Ractor proxies, Promise-like delegation, String/ArrayInquirer,
  Duration/TimeWithZone, OrderedOptions/configuration, OptionMerger,
  deprecation/broadcast logger proxies and Railtie delegation. Verdict:
  semantics bound for replacing an unknown name space with a fixed list;
  any cache-on-first-use design needs its own invalidation/visibility tests.
  No evidence here justifies such a change.
- Testing/system-test/assertion/fixture/time-stub helpers, migration dispatch,
  CI DSLs, commands/runner/query eval and Rails generators are explicitly in
  the index but not candidates for request speed. Their method bodies may be
  closures, Method copies or ordinary source; optimizing test registration or
  a generator's shebang is not an HTTP win. `output_safety.rb:221` evaluates a
  back-reference-setting Proc, not a request helper method.

## Measurements and stop decisions

### class_attribute: reject the remaining owner-reader rewrite

[#57317](https://github.com/rails/rails/pull/57317), implemented by
[9d4f4fa60c](https://github.com/rails/rails/commit/9d4f4fa60c), stores values
in owner ivars with attr_reader. Public real defs call the captured owner's
real internal reader. The screen replaces only that owner-getter closure
with a lexical constant-backed real method installed via UnboundMethod.
Five rotated samples, 2M warmup/5M calls per case, ordinary GC. M calls/s,
baseline → candidate:

| Hot read | Interpreter | YJIT | ZJIT |
|---|---:|---:|---:|
| Class reader | 21.64 → 23.49 | 37.10 → 35.95 | 30.91 → 33.82 |
| Instance reader | 15.33 → 15.79 | 32.01 → 30.60 | 29.80 → 30.80 |
| Class predicate | 15.08 → 16.03 | 34.54 → 33.79 | 40.16 → 41.06 |
| Inherited subclass | 21.58 → 24.02 | 37.25 → 36.61 | 31.26 → 34.22 |
| Subclass after override | 21.48 → 23.99 | 35.84 → 35.81 | 31.14 → 33.65 |
| Grandchild after override | 22.59 → 24.38 | 35.78 → 34.92 | 19.70 → 21.28 |
| Instance of overridden subclass | 14.86 → 15.99 | 31.30 → 31.96 | 29.34 → 31.24 |
| Per-instance override | 40.80 → 41.56 | 44.98 → 44.91 | 42.33 → 44.74 |

All steady-state paths allocate **0 objects/read** in both versions (fixed
measurement overhead amortized). This does not clear the YJIT gate, so do not
pay the extra constant/module complexity or claim full semantics verified.
In particular an own-ivar shortcut breaks duplicated classes: a duplicate
continues following its original owner until its own assignment.

Prior semantics checked in source/history: [#52717](https://github.com/rails/rails/pull/52717),
[#52722](https://github.com/rails/rails/pull/52722),
[#53606](https://github.com/rails/rails/issues/53606),
[#55786](https://github.com/rails/rails/pull/55786).
Singleton-class/instance-singleton handling, instance reader/writer/predicate
options, default, redefinition-warning suppression and Ractor ownership must
all remain intact in any future proposal. They were **not** certified by this
rejected performance screen; no full AS/AR suite result is claimed.

### delegated_type name: reject even the smaller interpolation hoist

`public_send("#{role}_class").model_name.singular.inquiry` creates a method-name
String on every invocation. A CodeGenerator version initially screened at
1.34–1.36× YJIT, 2 → 1 allocated objects/call, but three pinned processes
weakened the result to roughly 1.30×. Hoisting just the String (retaining the
closure and public dispatch) is a much smaller competing implementation.
It was therefore measured as the actual candidate, not dismissed merely
because it is not code generation.

An initial frozen-name approximation reached 1.251× YJIT. The final script
constructs the interpolated String once, as the actual proposed hoist would,
rather than substituting a frozen literal. The separate final runs below
supersede that approximation; both datasets are retained.

Three fresh processes per variant/mode pinned to CPU 0; baseline/candidate
order reversed in the middle pair; 500k warmup and five rotated 1M-iteration
samples. Two-receiver loops make two helper calls/iteration and are normalized
per helper call. Ordinary GC; median of all 15 samples, M calls/s:

| Workload | Interpreter baseline → hoist | YJIT baseline → hoist | ZJIT baseline → hoist | Objects/call |
|---|---:|---:|---:|---:|
| One receiver class | 1.368 → 1.609 (1.176×) | 1.948 → 2.348 (1.205×) | 2.033 → 2.419 (1.190×) | 2 → 1 |
| Two separately declared model classes | 1.268 → 1.473 (1.162×) | 1.966 → 2.372 (1.207×) | 2.044 → 2.453 (1.201×) | 2 → 1 |

Paired-process YJIT medians: one class **1.180/1.177/1.224×**; two classes
**1.190/1.172/1.243×**. This is not a clear repeatable 1.3× gain, and it has
**zero observed request calls** in Fizzy and Campfire anyway. No production
patch, focused tests, full suites, Thermos or PR draft is warranted.

Open/closed PR and issue searches for delegated_type + CodeGenerator/speed/
performance/interpolation found no equivalent proposal. Read original
[#39341](https://github.com/rails/rails/pull/39341); unrelated constructor
[#58019](https://github.com/rails/rails/pull/58019) is not this name helper.
These searches preceded any production edit (none was made).

  rewhere 24/36. A filter_map variant is worse: YJIT extraction
  **0.476/0.537×**, +1 allocation/extraction and +2/public merge. All 9 runs,
  31 operations each / 1,953 samples completed; 10-shape semantic checks and

## Lessons for Lowrail

| Lowrail unit / installation site | Action |
|---|---|
| `ar_instantiate.rb:47,58+` | Already emits a real `_load_from_sql` def, with per-plan identity, original fallback and row-by-row mutation checks. Keep that form; do not convert it to a captured-plan bmethod. |
| Endpoint/template factories (`endpoint_build.rb`, `templates.rb`, compiler-generated source) | Keep hot executable units as real defs, with descriptions/facts in explicit runtime state. Consider shared canonical bodies only when the complete body/facts contract is identical; never deduplicate by public name alone. |
| `inertia_config.rb:60` mutation wrappers | Already generated real defs. Source changes are unnecessary; configuration remains live and invalidates guards. |
| `ar_guard.rb:119` | Captures wrapper module + event and deliberately walks alias/super chains to avoid recursion. Not an enum-like rewrite. A real-def alternative needs a fresh correctness proof for aliasing, inherited visibility and suppressed-hook/mid-request mutation cases, plus net measurements. |
| `compilation.rb:211,233`, `endpoint_build.rb:192`, diagnostic route/oracle hooks | Build/capture/visitor/diagnostic closures, not established request hot paths. Rewriting these cannot be counted as faster emitted application code. |
| Guarded/sealed query and render programs | Spend effort on whole nonescaping programs identified by Bet C, not on blanket closure replacement. Emit ordinary methods at the compiler boundary while preserving evaluation order, arbitrary user effects, lazy loading and fallbacks. |

Do **not** add an eager ActiveSupport::CodeGenerator dependency to Lowrail
setup, force app/framework constants to load, weaken manifest guards or
promote quarantined passes based on these microbenchmarks. No Lowrail runtime
behavior changed in this study. There is no demonstrated reason here to
patch CodeGenerator itself: sharing policy, boot eval cost and source-location
tradeoffs need separate memory/boot measurements, not speculation.

## Final bounded track: profile-driven query allocations

**Reject; close the Rails track for now.** Allocation reductions alone did not
produce the requested **1.15× YJIT** query-building improvement. This follow-up
changes no Rails or Fizzy production code and makes no whole-request claim.
It does not establish that all possible Active Record optimizations are exhausted.

### Standalone reproduction and attribution

[The standalone script](../bench/experiments/rails_query_allocations.rb) loads
Fizzy's actual SQLite schema at the historical source pin above (SHA256
`5417f9d264a0ad3b1423c64b7a5622bccb0dc6bee5267d5859ac99539d44aff9`)
into an in-memory database. It defines only the associations, enum types and
scopes needed by nine representative buckets/card-show query chains. It does
not boot or patch Fizzy. Rails remains the measured main pin
`5e732a78bf708e7f1d649de4b6ebf00d86daaabc`; Ruby remains master `5771bd7a3910`.

The source chains come from `buckets_controller.rb:5–6`,
`views/buckets/_bucket.html.erb:4`, `concerns/bucket_scoped.rb:7`,
`bubbles_controller.rb:39`, `views/bubbles/show.html.erb:48–49`,
`bubble/assignable.rb:16`, `bubble/messages.rb:5`, and
`views/bubbles/_comments.html.erb:1–3`. The complex cards chain retains
`where.missing(:pop)`, the published-or-own-draft OR, the association predicate,
ordering and limit. Message scopes retain their two-column order and delegated
type condition. Scalar identifiers are asymmetric; actual queries execute
against rows that distinguish inaccessible buckets, other people's drafts,
popped cards, inactive/system users and the wrong message type.

This is a bounded **query-construction** study, not an HTTP replay or a complete
page profile: authentication, saved-filter subgraphs, attachments, rendering,
SQL execution and statement-cache lookup are outside the measured loops.
`find`/`exists?` predicates are reproduced as fresh relations with their
appropriate limits/projection, not claimed as measurements of those terminal
APIs. Association proxies/base scopes are warmed and reused; each measured
relation and its Arel are fresh. `build` stops at the relation; `arel` includes
the deferred joins/node tree. No `.to_sql` or database work is timed.

### Prior work, then one prototype

Open/closed issue and PR searches preceded the prototype. Existing merged
[#59185](https://github.com/rails/rails/pull/59185),
[#59239](https://github.com/rails/rails/pull/59239),
[#59165](https://github.com/rails/rails/pull/59165) and
[#59170](https://github.com/rails/rails/pull/59170) already remove the obvious
duplicate normalization/empty-order/constant-node work. Open
[#59212](https://github.com/rails/rails/pull/59212) already targets throwing
away association scopes on the statement-cache reader path; this study does
not duplicate that proposal or measure cached reader execution.

Closed [#56635](https://github.com/rails/rails/pull/56635) tried a broad
predicate fast path and mutable WHERE concatenation. Maintainer feedback says
the complexity was not justified by throughput, while leaving room for small
measured allocation reductions. We do not resubmit those changes. Searches
for `merge_clauses`, WhereClause/empty/merge and having-clause allocations found
no equivalent proposal for the experiment below; existing merge/unscope
correctness [#53895](https://github.com/rails/rails/pull/53895) is unrelated.

The second plausible site, skipping empty extension forwarding, was stopped
at history review: [#57199](https://github.com/rails/rails/pull/57199) and
[#57246](https://github.com/rails/rails/pull/57246) already considered this.
Despite #57246's description mentioning a retained call-site guard, its actual
merged diff **removes** it and puts the empty guard in `extending!` instead.
[#58540](https://github.com/rails/rails/pull/58540) later removed unnecessary
flatten work. We did not reverse the accepted design or prototype that site.

The **only** prototype wraps the existing where/having merges in
`Relation::Merger#merge_clauses` with a check that **both clauses are empty**.
It leaves `from` replacement and every nonempty merge unchanged. Checking only
the incoming clause would be wrong: the original union also deduplicates the
existing predicates, even when the incoming clause is empty. Executed checks
include that asymmetric duplicate-predicate case, left/right/conflicting
conditions, `none`, nonempty HAVING and independent relation mutation.
The overlay is research code in the standalone script, not a Rails patch.
