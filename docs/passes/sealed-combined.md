# Combined passive form, token and collection study

**Untimed gates pass; no combined price yet.** This is one whole-request
interpreter `GET /articles/1` experiment, not a sum of the isolated prices.
Only form has a production certificate. Token and collection are explicitly
pricing specimens; no pass promotion, default change, filter flattening or
whole-app support follows from this study.

The [adapter](../../bench/experiments/sealed_combined.rb) retains the real
passive form unit. It uses the accepted token/collection render operations,
but not their effectful micro installers. Two targeted observers capture
the partial and proxy during real original rendering. After that original
form it attaches the same named view variant in off and on arms, disables
both observers, and keeps actual-holder checks, live SQL, partial templates,
events, URLs, token generation/masking and global epoch deopt. No view
construction, template lookup/compilation, objspace fallback or materializing
runtime inventory is used. This adapter certifies only this single-threaded
pricing workload; it is not production token/collection admission.

## Combined-artifact review gate

The [checker](../../bench/experiments/sealed_combined_check.rb) reuses the
production cold worker/comparator with explicit `expected_jit: "interpreter"`.
Its default remains actual production/YJIT. Interpreter workers disable Rails'
automatic YJIT before initialization and assert actual interpreter mode
afterwards. They never forge the reported VM mode.

The fresh artifact has **one `sealed/form_scaffold` unit, zero delivered
files/templates**. Before timing, the combination itself must pass:

- Off/off/on cold boot, index, first original show and natural repeat show
  for both declared entropy seeds, with complete Object/Kernel/BasicObject,
  certified-holder and cached-view ancestry, bound owners, instance source
  locations, feature order, hooks, SQL streams, events and parent-read exit
  effects. Neither `Templates::CompiledSource` nor `PreloadPlans::Hook` occurs
  in any arm. No ancestry filtering or feature normalization.
- **192 ordinary + 192 header-writing-subscriber pairs**, byte-identical
  status/body/all headers, ordered SQL, captured events and assigns. Each
  on arm records **form104/token281/collection104**, zero fallbacks/refusals.
- **50** separate warm native requests: **form50/token200/collection50**,
  zero fallbacks. The first natural show remains original (form0); its repeat
  records form1/token4/collection1.

Raw unpinned workers remain `rejected_off_control` for independent entropy
and real clock headers. Both declared seeded comparisons have zero off/off
and off/on differences, no boot SQL and no capture errors. These are bounded
scenario checks, not proof of arbitrary subscriber payloads or all app inputs.
Correctness companions use declared entropy/secret controls; counters use
real entropy. The broader all-sealed artifact remains independently red for
its Template/Preloader chains and on-only installer features.

The initial stronger feature census found on-only `compilation.rb`, `loader.rb`
and `routes.rb`. Explicit `LOWRAIL_SEALED=1` now defines those helpers in both
arms without installing their compiler/eval/route hooks. Default startup and
guard invalidation are unchanged. The all-sealed threaded regression retains
its scoped seam-feature check; the isolated combined gate additionally
compares **every Lowrail feature in actual load order**. It does not silently
rename broader all-sealed failures to passes.

Development failures remain private: the first checker used a relative worker
path; the next exposed feature asymmetry; a stale artifact then correctly
refused after the setup edit. A later paired check cleared Rails' DUMMY secret
between arms and therefore rejected literal tokens/cookies; the corrected
paired fixture explicitly declares the same disposable secret. These were
untimed development checks, not counter retries or suppressed mismatches.

failure, no errors, two skips**. The sole failure is the intentionally red

component bundle rejects the actual `x86_64-linux` platform, so that component
is **uncovered**. No preview timing or sealed-activation claim is made. This
does not substitute for the primary interpreter checks above.

**29.56 ms form + 21.70 ms token/collection** in one observation. These are
not controlled cold latency estimates and are not amortized into the warm
instruction result.
