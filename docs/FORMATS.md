# Data formats (v1)

All files are JSON, written under `<app>/.lowrail/`.

## facts.json — what the booted app looks like

Written by `gem/exe/lowrail-facts` (run inside the app as
`bundle exec ruby /abs/gem/exe/lowrail-facts OUT.json`; the app's Gemfile is
never touched). It sets `RAILS_ENV=test` unless set, starts the generated
code capture, requires `config/environment`, runs the materialize steps
(below; `--no-materialize`: only `Rails.application.eager_load!`), then
dumps. `lowrail facts APP [--out PATH]` runs it with cwd APP and writes
`APP/.lowrail/facts.json` and `APP/.lowrail/generated/<sha256>.rb`. Raw observations only; classification (e.g.
"generated by `has_many`") happens in Rust (`src/facts/origin.rs`), where
Prism can look at the source span.

Methods are listed per module for the methods **owned by or visible on** that
module: public, protected and private `instance_methods(false)` on the module
and on its singleton class (`"singleton": true`), so the dump stays linear in
the app size. Resolution facts (`Article#title` → owner) for a receiver are
derived from the ancestors chain. `owner` differs from the module (or
`#<Class:Mod>` for singleton methods) when `instance_methods(false)` reports
methods of a prepended module or a ZSUPER entry (`private :inherited_method`);
61 such methods in real-blog.

`iseq_kind`: `method` (a `def`, also when it is the body of
`define_method(:x, instance_method(:y))`), `block` (`define_method` with a
block), `eval` (source path `(eval at FILE:LINE)`, i.e. string eval without a
file argument), `cfunc` (no ISeq, no source), `attr_reader` / `attr_writer`
(no ISeq but a source location), `none` (anything else without an ISeq).
Rails passes `__FILE__, __LINE__` to its `class_eval` strings, so generated
methods are mostly `method` with a source location inside the gem.

Rules the dumper follows:

- **Order of side effects.** Materialize runs before the dump. Models are
  then dumped first (a no-op after materialize, but it keeps
  `--no-materialize` dumps complete): `load_schema` and
  `define_attribute_methods` run for every concrete model whose table exists,
  so attribute methods (otherwise defined lazily on first instantiation)
  appear under `Model::GeneratedAttributeMethods`. Modules are dumped next,
  templates last (compiling them autoloads handler code the boot did not).
- **Robustness.** Every per-module, per-method, per-model, per-controller,
  per-route and per-template step rescues and appends to `errors`
  (`kind: "error"`); models without a table are `kind: "skipped"`. Core
  reflection is bound (`Module.instance_method(:name).bind_call(mod)`), so
  modules overriding `name`, `inspect`, `respond_to?`, `method`, … and
  `BasicObject` subclasses are handled.
- **Anonymous modules** are counted, not listed (except the synthetic
  ones below); so are modules whose name
  is nested in an anonymous one (`#<Class:0x…>::Config`, `anonymous_rooted`)
  and singleton classes. Anonymous modules in ancestor lists appear with
  their address stripped (`#<Module:0x>`).
- **Determinism.** Everything except `timings` is identical across runs of
  the same app: modules sorted by name, methods by (singleton, name),
  models/controllers/templates by name, gems by name, features sorted.
  Routes stay in route-set order (that order is matching semantics).
- **Synthetic modules.** Anonymous modules that hold generated methods are
  listed under descriptive names with `"synthetic": true`: the compiled
  template container (`ActionView::LookupContext.view_context_class`, or
  `…::DetailsKey.view_context_class` before Rails 8.2), the route helper
  modules (`Rails.application.routes.named_routes.path_helpers_module`,
  `…url_helpers_module`), and every anonymous ancestor of a named module,
  under the first such module by name: `Widget._enum_methods_module`,
  `Widget._store_accessors_module`, else `Widget.ancestors[3]` (e.g.
  `has_secure_password`'s `InstanceMethodsOnActivation`).
- **Templates** cover every file under `ActionController::Base.view_paths`
  that lie under the app root. `code` is what `ActionView::Template#compiled_source`
  passes through as `code = @handler.call(self, source)` (after
  `strict_locals!` and `encode!`); Lowrail can compile the same method body.

### Materialize steps

Each step calls Rails' own entry points, is guarded (failures go to
`errors` as `materialize <step>` or a narrower `where`), and reports the
delta of a census over every module (named, anonymous, singleton) of
modules, own methods, and compiled scripts. `census_boot` is the census
right after `config/environment`.

| step | what it forces |
|---|---|
| `eager_load` | `Rails.application.eager_load!` (every Rails autoloader) |
| `production_eager_load` | the rest of production's eager load: `:before_eager_load` hooks, `Zeitwerk::Loader.eager_load_all`, `Rails.eager_load!`, every `eager_load_namespaces` entry |
| `models` | per concrete model with a table: `load_schema`, `define_attribute_methods`, association `klass` and `inverse_of`, `relation_delegate_class` |
| `relation_delegation` | speculative: `generate_relation_method` for every public class method defined in app source (Rails does it on the first call through a relation) |
| `routes` | `reload_routes_unless_loaded` (lazy routes, Rails 8.0+), `finalize!`, `url_helpers`, `mounted_helpers` |
| `controllers` | `action_methods` and `view_context_class` for every controller and mailer |
| `middleware` | `Rails.application.app` (the Rack stack) |
| `i18n` | `I18n.eager_load!` |
| `templates` | every file under the controller and mailer view paths (app and engines) compiled into the real template container; non-strict-locals templates for an empty locals list (`compiled_templates`) |

### Generated scripts

`Lowrail::ScriptCapture` (`TracePoint(:script_compiled)`, installed before
`config/environment`) records every string compiled by `eval`,
`class_eval`, `module_eval`, `instance_eval` or `Binding#eval`; files are
not recorded. One entry per distinct (digest, ISeq path, ISeq first line,
receiver module, caller); `count` is the number of compilations. `path` and
`lineno` are what eval was given (`(eval at FILE:LINE)` and 1 without a
file argument): script line *k* is reported as `lineno + k - 1`. `kind` is
the eval method, `caller`/`caller_label` the code that called it, `module`
the receiver (its class for `eval`), `phase` `boot`,
`materialize:<step>` or `dump`. The source is in
`generated/<sha256>.rb` next to facts.json.

A method's `script` is set when its ISeq was compiled inside a captured
script (identity of the ISeq, through `InstructionSequence#each_child`),
including `define_method` blocks inside the script and methods whose
`source_location` points into a real gem file because eval was given
`__FILE__, __LINE__`. `src/facts/generated.rs` finds the exact `def` (or
call) at the relative line with Prism; untagged methods are matched by path,
line range and a `def` of that name as a fallback. `lowrail facts APP --show
Mod#meth` prints a method's origin and generated body.

## observed.json — what a test run builds and which types flow

Written by `lowrail observe APP [--samples N] [--method Mod#meth]...
[--no-types] [--facts PATH] [--overhead] [--no-run] [-- TEST COMMAND]`
(default command `bin/rails test`). The command runs with
`RUBYOPT="-I<gem>/lib -rlowrail/observe"`, `LOWRAIL=0` and
`PARALLEL_WORKERS=1` (unless set); no app file changes. Every process that
boots writes `.lowrail/observe/observed-<pid>.json` at exit; `lowrail
observe` merges them (definitions by module/singleton/name, scripts by key
with summed `count`, types with summed counts).

```json
{
  "format": 1, "app_root": "/abs", "ruby_description": "...",
  "command": ["bin/rails", "test"], "seconds": 40.5, "exit_ok": true, "processes": [59597],
  "modules_at_boot": 6503, "modules_after_boot": 6379,
  "defined_after_boot": [{
    "module": "Widget::GeneratedRelationMethods", "name": "cheapest", "singleton": false,
    "visibility": "public", "owner": "...", "source_location": "...", "parameters": [],
    "iseq_kind": "method", "script": "<sha256>", "module_new": true
  }],
  "generated_scripts": [{"...": "as in facts.json", "phase": "boot | test"}],
  "generated_stats": {"scripts": 2856, "compilations": 2900, "bytes": 1600000, "hook_seconds": 0.04},
  "samples_per_method": 16, "hooked_methods": 586,
  "types": [{
    "module": "#<Class:Room::MessagesCount>", "name": "ensure!", "singleton": true,
    "source_location": "/abs/app/models/room/messages_count.rb:12",
    "calls": 16, "saturated": true,
    "self": {"#<Class:Room::MessagesCount>": 16},
    "args": {"connection": {"ActiveRecord::ConnectionAdapters::SQLite3Adapter": 16}},
    "returns": {"Array": 9, "NilClass": 7}
  }],
  "timings": {"59597": {"boot_seconds": 2.2, "snapshot_seconds": 0.07, "hook_install_seconds": 0.13,
                        "exit_seconds": 0.48, "process_seconds": 40.3}},
  "comparison": {
    "facts": "/abs/.lowrail/facts.json", "defined_after_boot": 19524,
    "in_facts": 13677, "in_facts_by_script": 1322, "templates_compiled_in_facts": 79,
    "not_in_facts": 4446, "by_source": {"app test code": 735, "gem mocha": 431, "template": 80},
    "by_module": {"ActiveSupport::TestCase": 124},
    "methods": [{"module": "...", "name": "...", "singleton": false, "source": "gem mocha", "source_location": "..."}]
  }

```

- **Boot** is the `after_initialize` load hook (config/environment
  loaded, before test files): the recorder snapshots every module's own
  method names there. `defined_after_boot` is every method whose name was
  not in its module at boot (`module_new`: the module itself is new).
  Anonymous modules carry the facts' synthetic names where they apply,
  else `#<Class < Super>` / `#<Module>`.
- **Types** are sampled for app methods (source under the app root, not
  `vendor/`, `tmp/`, `test/`, `spec/`), hooked at boot and as Zeitwerk loads
  app constants, plus `--method` framework methods. Each method gets its
  own `TracePoint(:call, :return)` enabled with `target:`, which
  instruments only that ISeq and disables itself after `samples_per_method`
  returns (`saturated`); cfuncs and attr methods cannot be targeted.
  Classes are the shallow `obj.class` (core reflection, never the object's
  own methods); anonymous `*`/`**`/`&` parameters are not sampled.
- **comparison** (when facts.json exists): a method counts as in the facts
  by module and name, by the same generated script digest or the same name
  and generated `def` text (CodeGenerator's shared method caches), or, for
  compiled template methods, when the facts compiled the same template
  file. The rest is grouped by where its body comes from.

## manifest.json — what the runtime gem loads

Written by `lowrail build` (via `gem/exe/lowrail-compile`).

```json
{
  "format": 1,
  "ruby_description": "...",
  "compile_option": "<sha256 of sorted RubyVM::InstructionSequence.compile_option>",
  "rails_env": "test",                                  // units apply only in this env
  "files": {"/abs/app/helpers/rooms_helper.rb": {"iseq": "iseq/<sha>.bin", "source_sha256": "..."}},
  "templates": {"/abs/app/views/articles/_article.html.erb": {
    "source_sha256": "...", "code": "<lowered compiled ERB code>", "units": [0, 1]}},
  "units": [{
    "id": 1, "kind": "template", "file": "/abs/app/views/articles/_article.html.erb",
    "pass": "route/path", "sites": 3,
    "facts": [
      {"receiver": "@self", "method": "article_path", "owner": null,
       "source_location": "/abs/gems/actionpack-8.1.4/lib/action_dispatch/routing/route_set.rb:334",
       "visibility": "public",
       "route": {"name": "article", "spec": "/articles/:id(.:format)", "parts": ["id"],
                 "defaults": "{controller: \"articles\", action: \"show\"}"}},
      {"receiver": "ActionDispatch::Http::URL", "method": "path_for", "singleton": true,
       "owner": "#<Class:ActionDispatch::Http::URL>", "source_location": "/abs/...:169", "visibility": "public"}
    ]
  }]
}
```

Units: `kind` is `"template"` (code served through the template seam,
`file` is the template identifier) or `"file"` (a Ruby file served through
`load_iseq`); `pass` names the lowering pass (`view/link_to`, `route/path`);
`sites` counts lowered call sites. Unit ids are unique across passes.

Facts: a method fact holds when `receiver#method` (or `receiver.method` with
`"singleton": true`) resolves to that owner, source location and visibility
(`owner: null` = an anonymous module, matched by source location).
`"receiver": "@self"` means the class of `self` at the call site: lowered
code calls `::Lowrail.ok?(id, self.class)` and the facts are checked per
class, cached until a hook resets the unit (`"@view"` from earlier builds is
read the same way). A fact with `"route"` additionally requires the method to
be owned by `Rails.application.routes.named_routes.path_helpers_module` and
the named route to still have that path spec, required parts and
`defaults.inspect`, with no requirements and no glob.

## build input for lowrail-compile — `units.json`

```json
{"out": "/abs/app/.lowrail", "rails_env": "test",
 "files": [{"path": "/abs/app/models/article.rb",
            "lowered": "/abs/app/.lowrail/src/app__models__article.rb",
            "original": "/abs/app/.lowrail/src/app__models__article.rb.orig"}],
 "templates": { ...as in manifest... },
 "units": [ ...as in manifest... ]}
```

`lowrail-compile` compiles each lowered source with
`RubyVM::InstructionSequence.compile(src, path, path, 1)` (path = original
absolute path), writes binaries, then atomically writes `manifest.json`. A
file is skipped (and its units dropped) when its current SHA-256 differs from
`source_sha256` or, if given instead, from the SHA-256 of the `original` copy
the pass lowered. `templates` and `rails_env` are copied to the manifest;
template units need no compiled file.

## ledger.json — every site a pass looked at

Written by `lowrail build`. One entry per (file, line, helper, outcome):

```json
[{"template": "/abs/app/views/articles/_article.html.erb", "line": 13, "pass": "route/path",
  "helper": "edit_article_path", "outcome": "lowered", "copies": 2},
 {"file": "/abs/app/models/webhook.rb", "line": 45, "pass": "route/path",
  "helper": "message_path", "outcome": "Webhook#message_path is defined by Webhook, not the route set"}]
```

`template` or `file` names where the site is; `outcome` is `"lowered"` or
the reason it was not. `copies` > 1 when the same call occurs several times
in the code a pass saw (a route helper inside a lowered `link_to` appears in
both its fast path and its fallback). Denylisted units appear as
`{"line": 0, "helper": "*", "outcome": "denylisted by verify --bisect"}`.

## verify outcomes — `outcomes-<mode>.json`

Written by the Minitest or RSpec reporter (`LOWRAIL_OUTCOMES=path`), both
installed through `RUBYOPT=-rlowrail/setup`, without app/Gemfile changes:
`{"tests": {"ArticleTest#test_x": {"result": "pass|fail|error|skip", "failure": "Class: first line"}}, "unit_hits": {"0": 12}}`.

RSpec keys are `example.id` (file plus scoped example id), not descriptions,
which can be duplicated. RSpec passed/failed/pending map to pass/fail/skip;
failed expectations and unhandled exceptions both use RSpec's failed status.
Failures include the exception class and full message (expectation messages
often start with a blank line), with object addresses masked. Pending examples
include their exception or skip reason; unexpectedly passing pending examples
remain failures. Each RSpec process writes `path.<pid>`; Minitest also writes
an aggregate `path` after its forked workers finish. Verify reads the aggregate
when present, otherwise the per-process files, so hits are not counted twice.
Use `lowrail verify APP -- bundle exec rspec --seed 12345` for RSpec; custom
test commands are also accepted by `lowrail observe`.
