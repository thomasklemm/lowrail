    Don't freeze serialized column defaults
    
    Since a model's default attributes are frozen when every one is
    freezable, freezing casts each default once and every new record
    deep-dups the cast value. For a serialized attribute the coder decides
    that value, and it may not round-trip the column default: a coder that
    loads a NOT NULL jsonb default '{}' as [] makes the attribute of a new
    record read as changed before anything touched it, so it is saved, and
    since that coder also loads nil as [], the serialized type writes [] as
    NULL.
    
    Types now say whether their defaults can be frozen. Serialized types
    can't, even with a NULL default, since the coder may load NULL as a
    value that reads as changed; an encrypted type asks the type it
    encrypts, and decorators such as normalized and time zone aware types
    are delegators, so they answer for the type they wrap. A model with a
    serialized attribute gets writable defaults again, so its defaults are
    not cast at schema load and each record casts its own.
