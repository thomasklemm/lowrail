Add a blog benchmark that writes

The Rails benchmarks here mostly read. In their timed iterations none
of them submits a form, fails a validation, or runs after-commit
callbacks and broadcasts; lobsters' only writes are its read-ribbon
bookkeeping. Real apps spend much of their time saving records:
validations, callbacks, transactions, INSERT/UPDATE/DELETE and
enqueuing jobs.

The app is Sam Ruby's create-blog from roundhouse-rb/roundhouse (MIT):
rails new --css tailwind on Rails 8.1.4.1, with Article and Comment
scaffolds, validations and Turbo broadcasts. It keeps the production
defaults of rails new: SQLite, Solid Cache, Solid Queue, Solid Cable,
Propshaft and importmap, no external services. The built Tailwind CSS
is checked in, so no CSS build runs. benchmarks/blog/README.md lists
the few changes to the generated tree.

Each iteration runs 200 seeded visits in-process, like railsbench:
reads (index, show, JSON) and writes (create, update and delete
articles, add and delete comments, a create that fails validation
with 422). Writes submit the CSRF token from the page's form, as a
browser does, and every response's status is checked, along with a
body marker or the redirect target. The iteration runs in one
transaction per database that is rolled back at the end, as in Rails
tests, so every iteration sees the same rows and IDs. Rails 8.1 opens
that transaction in pin_connection!; Rails main no longer does
(rails/rails 9e8fe3955b), so benchmark.rb opens it itself when none is
open, and works on both. Time.now starts
at a fixed date and advances one second per visit, so the work doesn't
depend on the date and updates still write updated_at. Bootsnap is
disabled, so Ruby builds that share a RUBY_DESCRIPTION don't load each
other's cached bytecode.

Saves run as savepoints inside that transaction, and their
after-commit callbacks run when the savepoint is released, as in Rails
tests. Solid Cable inserts each broadcast in the request rather than
on its batching writer thread, so it lands in the transaction; the
later broadcasts are enqueued into Solid Queue. Since nothing commits,
a real COMMIT is not measured.
