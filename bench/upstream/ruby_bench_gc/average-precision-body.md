The "Average marking time" and "Average sweeping time" lines that `--harness=gc` prints are rounded down to whole milliseconds. `GC.stat(:marking_time)` and `GC.stat(:sweeping_time)` count whole milliseconds, so each iteration's value is an Integer, and `harness/gc.rb` divided their sum with Integer division. For example, three iterations that mark 1, 0 and 0 ms print `0.0ms` instead of `0.3ms`. The error of up to 1 ms matters when marking takes a few milliseconds per iteration, as on railsbench with ZJIT (eight minor GCs of about 0.35 ms each). This uses `fdiv`. The results JSON and the summary tables don't go through these two lines, so nothing else changes.

The new test runs the harness with stubbed GC samples and fails on main. I found this while measuring GC time for ruby/ruby#19685, alongside XrXr's #562 (timings without GC time) and eightbitraptor's #541 (GC per ruby table).
