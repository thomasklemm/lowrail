## Demonstrated differences, including their smallest exactness alternatives

### 1. The new CGI decoder can be intercepted after URI loads

On MRI 4.0.10, master, master with ZJIT, and JRuby 10.1, a prepend on
`CGI.unescapeURIComponent` which returns `super + '!'` changes
`URI.decode_uri_component('a%41+b')` from `"aA+b"` to `"aA+b!"` only on the new head.
A singleton implementation returning `"intercepted"` supplies those bytes; returning the same frozen string
causes `FrozenError` at the final `force_encoding`. Base and the previous head ignore that CGI method.

The native check is evaluated when URI loads. With a Ruby wrapper installed **before** URI, the new head takes
the `gsub` fallback and returns `"aA+b"`, matching base. Removing the optional CGI decoder before loading also
works. MRI 2.5, pure-Ruby CGI and TruffleRuby retain the fallback and do not acquire this interception path.

This extends the accepted `CGI.unescape`/frozen-CGI-result boundary to another public CGI method. If preserving
arbitrary CGI overrides were required, the smallest behavior-preserving alternative is to keep `gsub` for
`decode_uri_component`; capturing a Method object would still observe overrides present at load and would create
different reload semantics. No such change is requested here.

Evidence: `adversarial.rb overrides`, all engines' `*-overrides.jsonl`; MRI 4.0.10
`*-load-hook-wrapped_before.jsonl` and `*-load-hook-no_native.jsonl`.

### 2. Custom objects returned by `b` expose another method's hooks

On the new native URI path, a String returned by a custom `b` with a public `gsub` that raises
`"intermediate gsub"` now decodes successfully to `"bB+c"`; base and the previous head raise. Making that `gsub`
private changes the base error to `NoMethodError`, while head still succeeds. Original-input singleton methods
are not skipped: the original `b` continues to run.

An even smaller illustration uses a custom `b` returning an object with `gsub` and `to_str`:

```ruby
middle = Object.new
def middle.gsub(*); "from gsub"; end
def middle.to_str; "b%42+c"; end
input = "%41".dup
input.define_singleton_method(:b) { middle }
URI.decode_uri_component(input)
# base / previous: "from gsub"
# new native path: "bB+c"
```

Returning nil, an Integer or a Symbol from `b` changes `NoMethodError` for `gsub` into native CGI's `TypeError`.
These differences are present on MRI 4.0.10/master and JRuby 10.1; the fallback URI decoder retains the old behavior.
The analogous form-decoder behavior already exists on `c43954f`. On pure CGI and TruffleRuby, a custom form
intermediate's public/private `tr` is newly called relative to base, but was already called by `c43954f`.

The earlier thermos report explicitly assessed the custom-intermediate `gsub` boundary, even though the compact
accepted-boundary list in the brief did not mention it. This head extends that assessment to the URI decoder.
Preserving these arbitrary intermediates would require keeping their `gsub` path; adding normalization or type
guards would itself alter conversions and hooks. No guard or normalization is requested.

Evidence: `adversarial.rb objects`, `intermediates.rb`, `results/*/*-intermediates.txt`; previous-head controls
on MRI 4.0.10, MRI 2.5, pure CGI, master, TruffleRuby and JRuby 10.1.

### 3. CGI reflection overrides can now fail URI loading

Executed on MRI 4.0.10:

```ruby
require 'cgi/escape'
def CGI.method(name); raise 'CGI.method called'; end
require 'uri'
# base / previous: loads and decodes "aA+b"
# head: RuntimeError: CGI.method called
```

A singleton `CGI.respond_to?` that raises similarly prevents loading only on head. This is an additional
load-time hook surface, distinct from merely loading CGI earlier. Ordinary CGI-first, URI-first, CGI autoload,
standalone `uri/common`, and common.rb reload all work in the executed matrix.

The smallest way to eliminate this new reflection surface is to keep the URI `gsub` implementation and remove
its native-method detection. Bypassing Ruby reflection via bound core methods would add defensive machinery
for deliberately modified CGI objects. Neither is warranted for the documented String-decoding contract.

Evidence: `load_hooks.rb`, `results/4.0.10/{base,previous,head}-load-hook-{method_raises,respond_raises}.jsonl`.

### 4. The already-accepted private-helper boundary changes shape

A private `_decode_uri_component(regexp, str, enc)` prepend forwarding with `super` works on base. On head it
raises `ArgumentError: wrong number of arguments (given 2, expected 3)` for both public decoders. The previous
head bypassed this helper for form decoding and retained its old signature for URI decoding. Public URI decoder
prepends continue to work on all tested paths.

Keeping the private helper's original three-argument signature would preserve this particular forwarding
prepend, but not arbitrary implementations that ignore the new block. This is within the explicitly accepted
private-helper boundary; no compatibility shim is requested.

The already-accepted earlier CGI load is also observable: base leaves `CGI` undefined, or leaves its autoload
pending; head defines it/consumes that autoload. This is unchanged from the previous head. A lazy require would
remove that particular loading difference but introduce first-call/thread/Ractor considerations; no such change
is requested. JRuby 9.4's previously accepted subclass exception was **not rerun** in this requested matrix.

## Each added assertion catches a plausible wrong implementation

Extracted both test methods from the exact head using Prism, verified that extraction against the retained
assertion list, and executed each assertion independently against generated mutants on MRI 2.5, MRI 4.0.10,
pure CGI and TruffleRuby. The real test-unit suite also ran; the mutation runner's small assertion helpers are
not substituted for that suite. Head and the original base pass the new assertions.

| Added assertion, test_common.rb lines | Demonstrated wrong implementation it rejects |
| --- | --- |
| Mixed-case UTF-8 escapes, 213 / 272 | Removing final `force_encoding`; the URI case also rejects an uppercase-only fallback regexp. |
| Binary `%FF` to default UTF-8, 214 / 273 | Removing final `force_encoding` leaves BINARY instead of UTF-8, despite identical byte content. |
| GB18030 literal bytes plus `+`, 215 / 274 | Swapping the native decoders gives the wrong plus behavior. Dropping `b` makes the form assertion crash actual TruffleRuby in `String#tr`; the head passes. |
| Empty string, 217 / 276 | An empty-input early return yielding nil; the URI assertion also rejects `gsub!` returning nil on the fallback path. |
| Ordinary subclass, 218 / 277 | Dropping `b` leaves a subclass on the native no-escape path. Dropping the native-only guard makes the URI test fail on TruffleRuby because its Ruby CGI decoder preserves that subclass. |
| Invalid `%zz`, 223 / 282 | Validation using `\w\w` instead of hex digits accepts the malformed escape. |

Each tests an observable result, not allocation counts or calls to a particular helper. The `%zz` assertions
overlap the existing `x%a_` coverage for the demonstrated `\w` mutant; they are useful examples but not a new
independent barrier. The empty assertions do not by themselves check encoding or freshness. These limitations
do not invalidate the assertions. The subclass assertion's known JRuby 9.4 failure remains the accepted boundary,
not evidence that that runtime's suite passes.

The TruffleRuby no-`b` mutant terminated the process with an internal `ArrayIndexOutOfBoundsException` at the
GB18030 form assertion, so later assertions in that particular mutant process did not run. Its stderr and partial
stdout are retained. This is mutation-test evidence for retaining the copy, not a crash of the proposed head.
