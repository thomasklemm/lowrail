## Verdict: changes

No wrong result was found: the head matches master on every input I ran. Three things should change before this
replaces the PR head, and a few smaller ones would make it read more like the file around it.

**Must change**

1. **`decode_www_form_component` gets slower on TruffleRuby**, 2.3 to 15 times on short and plain strings. The
   head keeps cgi's Ruby decoder away from `decode_uri_component` but not from `decode_www_form_component`. Gate
   both methods on the one check that is already there (diff below), or say it in the body.
2. **"matched and looked up in Ruby" is false** in the body and the commit message. `String#gsub` with a Hash runs
   in C.
3. **The body leaves out the new `require "cgi/escape"`** and says both methods decode "in native code", which the
   head does not do on TruffleRuby. It has 179 words of prose and a six-row table.

**Optional:** `Encoding::ASCII_8BIT` as in the rest of the file; the conditional laid out as ruby/erb does it
(no `# :nodoc:`, the reason on the `else`); a clearer helper comment; `assert_instance_of`; four test lines that no
mutant needs; a shorter commit message. Details and diffs are below.

## Must change

### 1. TruffleRuby gets slower, because only one decoder is checked

TruffleRuby's cgi/escape is the Ruby file cgi ships (`lib/mri/cgi/escape.rb`). Its `CGI.unescape` starts with
`string.tr('+', ' ')`, and `String#tr` costs about 600 ns per call on TruffleRuby 40, for a five-byte string
(`logs/truffleruby-cgi-unescape-steps.txt`). The `gsub` that master runs takes about 40 ns there.

ns per call on TruffleRuby 40.0.0, best of 9 windows after 6 s of warm-up, each process on two cores of its own,
results kept in a global (`tbench.rb`, `truffle-time/`):

| `decode_www_form_component` | master | head | master again | head / master | single check / master |
| --- | ---: | ---: | ---: | ---: | ---: |
| `"hello"` | 47.9 | 722.2 | 45.4 | 15.5x | 0.98x |
| `"article%5Btitle%5D"` | 752.7 | 1,935.2 | 775.7 | 2.5x | 0.96x |
| `"Hello+world+from+Rack"` | 841.7 | 866.6 | 977.5 | 0.95x | 0.89x |
| 248-byte cookie | 954.1 | 2,375.5 | 947.1 | 2.5x | 0.99x |
| 16 KiB of `a` | 12,313 | 47,842 | 12,299 | 3.9x | 1.05x |
| 16 KiB of `%E3%81%82` | 1,441,703 | 452,064 | 1,414,210 | 0.32x | 0.94x |

These are the second of three runs. Over all three the head is 14.6x to 15.5x, 2.5x to 2.8x, 0.95x to 1.06x, 2.1x
to 2.5x, 3.8x to 3.9x and 0.32x to 0.33x of master, with master against master between 0.93x and 1.16x; the single
check, in runs 2 and 3, is between 0.87x and 1.06x. This is wall time on an 8-core orb, not the a1.xxlarge cohort
DECISIONS asks for before a number goes into a body: it shows the size of the effect and nothing finer.

`decode_uri_component` keeps the `gsub` on the head, and three of its four cases stay between 0.92x and 1.11x. The
fourth, `"user%40example.com"`, came out at 1.56x, 1.19x and 1.53x of master on the head, and at 0.96x and 1.00x
with the single check. I have not explained that difference.

The earlier reviews measured cgi's Ruby decoder on MRI (thermos-sol: +89% instructions for 16 KiB plain) and warned
not to claim an all-runtime win, but none timed TruffleRuby itself. Rack calls this method for every query
parameter and cookie value, most of them short and plain, so this is the common case on a runtime ruby/uri tests in
CI.

The cause in the code: the availability check asks whether `CGI.unescapeURIComponent` is native, and only
`decode_uri_component` looks at the answer. Described out loud, the head is "where cgi/escape has a native
`unescapeURIComponent`, `decode_uri_component` uses it, otherwise `gsub`, except `decode_www_form_component`, which
always uses `CGI.unescape`". The "except" is the part to remove.

**Recommended: one check, both methods (`variants/v-native-vs-b0f2bb7.diff`).** Where cgi/escape decodes
natively, both methods use it; elsewhere both keep the lines master has today:

```ruby
  if CGI.respond_to?(:unescapeURIComponent) && !CGI.method(:unescapeURIComponent).source_location
    # Returns a string decoded from the given \URL-encoded string +str+.
    # ... (the existing documentation, unchanged) ...
    def self.decode_www_form_component(str, enc=Encoding::UTF_8)
      _decode_uri_component(str, enc) {|bytes| CGI.unescape(bytes, Encoding::ASCII_8BIT) }
    end

    # Like URI.decode_www_form_component, except that <tt>'+'</tt> is preserved.
    def self.decode_uri_component(str, enc=Encoding::UTF_8)
      _decode_uri_component(str, enc) {|bytes| CGI.unescapeURIComponent(bytes, Encoding::ASCII_8BIT) }
    end
  else # cgi before 0.3.3, or cgi/escape written in Ruby
    def self.decode_www_form_component(str, enc=Encoding::UTF_8)
      _decode_uri_component(str, enc) {|bytes| bytes.gsub(/\+|%\h\h/, TBLDECWWWCOMP_) }
    end

    def self.decode_uri_component(str, enc=Encoding::UTF_8)
      _decode_uri_component(str, enc) {|bytes| bytes.gsub(/%\h\h/, TBLDECWWWCOMP_) }
    end
  end
```

`decode_uri_component` moves up five lines to sit beside `decode_www_form_component`; `encode_uri_component`
follows the block. The helper is the head's.

What this buys, each point run:

* TruffleRuby is back at master's speed (last column above; `truffle-time/run3-table.txt` agrees) and takes no
  path through cgi's Ruby code at all.
* **The JRuby 9.4 exception disappears.** JRuby 9.4.16.0 has a native `CGI.unescape` but no native
  `unescapeURIComponent`, so the check is false there and both methods run master's code: subclass inputs return
  String for `""`, `"a"`, `"a+b"` and `"a%41"`, and the suite has no failure, where the head has one
  (`logs/jruby-9.4.16.0.txt`). The body loses two sentences and the commit message its parenthesis.
* The decision really is taken once, for the whole change, and it reads as one sentence without "except".
* The GB18030 assertions lose their purpose: they pin a crash in `String#tr` inside cgi's Ruby `unescape` on
  TruffleRuby, which no longer runs.

What it costs:

* The lib diff against master grows from 16 added and 8 removed lines to 51 and 40, because the 30 lines of
  documentation above `decode_www_form_component` move one level in. Ignoring whitespace it is 21 and 10
  (`variants/diffstat.txt`, `variants/v-native-vs-48cda77-ignoring-whitespace.diff`). RDoc gives the documentation
  to the first definition only, and not to a comment above the `if` (tried both), so the documented methods have to
  be the `if` branch.
* Ruby 2.5 to 3.1.2 with their bundled cgi (before 0.3.3) keep today's speed for `decode_www_form_component` as
  well; the head speeds it up there. Those Rubies are past end of life, and they gain as soon as cgi is updated.
* Both methods are now defined twice. By the letter of the Readability gate a duplicated method under a
  capability branch is L3; the head already has one such pair. ruby/erb has the same construct for the same
  reason (`lib/erb/util.rb`: `if CGI.respond_to?(:escapeURIComponent)` ... `else # cgi.gem <= v0.3.2`), so it is a
  shape these maintainers have accepted. The item's note should say that this was weighed.

On MRI the native branch is the head's code: 4.0.9 interpreter, head and single check within 2.1% of each other
on all ten cases (`mri-time/run1-table.txt`). The body's numbers were measured on d09ffb7's tree, so they need a rerun
or a recorded equivalence before they are cited for a new tree.

**Smaller alternative: keep the code, add a sentence to the body.** For example: "On TruffleRuby, where cgi/escape
is written in Ruby, `decode_www_form_component` gets slower for short strings." It needs a number from a proper
cohort, keeps the JRuby 9.4 exception, and invites the question this review asks.

Looked at and not recommended:

* **`if CGI.respond_to?(:unescapeURIComponent)` alone**, as ERB writes it (`v-respond`). Simpler, but on
  TruffleRuby `decode_uri_component` then returns String subclasses as they are, since TruffleRuby's `String#b`
  keeps the subclass: `diff.rb` and `probe.rb` report differences and the suite fails at `test_common.rb:277`. It
  also leaves the slowdown.
* **`decode_uri_component` keeps its `gsub` everywhere** (`v-gsub`): no check at all and a four-line lib diff, zero
  differences everywhere I ran it. But only one caller gains, and the TruffleRuby slowdown stays.
* **`defined?(CGI::EscapeExt)`**, which hsbt uses in net-http, cannot stand in for `source_location`: cgi 0.5's
  `lib/cgi/escape.rb` defines that module itself, and TruffleRuby reports it as defined
  (`logs/truffleruby-facts.txt`). `source_location` is the one check that works across cgi 0.3 to 0.5, JRuby and
  TruffleRuby.

### 2. `gsub` with a Hash does not run "in Ruby"

Body: "so every `+` and `%XX` is matched and looked up in Ruby". Commit message: "which matches and looks up every
"+" and "%XX" in Ruby". `str_gsub` in `string.c` (v4.0.9) does the search, builds the key with `rb_str_subseq` and
calls `rb_hash_aref`, all in C. What it costs is a regexp match, a substring and a Hash lookup per escape: on
master, `decode_www_form_component` allocates 6, 7 and 8 objects for one, two and three escapes
(`logs/base-objects-and-cgi-gem.txt`). A ruby/uri reviewer will know this. Suggested wording for both places:

> ... and then run `gsub` with a regexp and a Hash, which costs a match, a substring and a Hash lookup for every
> `+` and `%XX`.

### 3. Body: the new require, the "native code" sentence, the length

* **uri now loads cgi/escape when it loads, and the body does not say so.** For a library with no requires
  outside itself this is the first thing its maintainer will look at. One clause is enough: cgi/escape ships with
  every Ruby, JRuby and TruffleRuby that uri supports (the suite passes on each). On Ruby 4.0.9 the require
  activates no gem, since cgi is no longer a default gem there (`logs/base-objects-and-cgi-gem.txt`).
* **Context for the coordinator, not for the body:** hsbt also vendors uri into RubyGems as `Gem::URI`
  ("Update vendored uri to 1.1.2", 2026-10-13; `lib/rubygems/vendor/uri/lib/uri/common.rb` at rubygems `fc37d0f`
  has only `require_relative` lines). Bundler loads that copy while it reads the Gemfile's `source` line
  (`bundler/source/rubygems.rb:378`), before it activates the bundle. On Ruby 3.2 to 3.4 cgi is a default gem, so
  a top-level `require "cgi/escape"` in the vendored copy would activate the default cgi first, and a different
  cgi version in the lockfile then conflicts. I read this in the RubyGems source and did not run it. He would have
  to patch the require out when vendoring, as net-http's vendored copy requires cgi/escape lazily inside one
  method (his commit d8fd39c in ruby/net-http, 2025-05-13). This may weigh against the PR whatever its code looks
  like; it is worth knowing before spending more rounds.
* **"both decode in one pass in native code"** is false for the head on TruffleRuby (`CGI.unescape` is Ruby there).
  With the single check it becomes true wherever cgi/escape is used.
* **Length.** DECISIONS asks for 50 to 120 words and treats 150 as the limit; the draft has 179 plus the table.
  Candidates to cut: the JRuby 9.4 sentences (gone with the single check), the list of what the helper keeps (the
  diff shows it; "same class, bytes and encoding" is the point), and two table rows (`"hello"` appears for both
  methods with the same result; four rows carry the message).

A body for the single-check shape, 146 words of prose with the link targets left out (numbers to be confirmed for
the new tree):

> `URI.decode_www_form_component` and `URI.decode_uri_component` copy the string with `b` and then run `gsub` with
> a regexp and a Hash, which costs a match, a substring and a Hash lookup for every `+` and `%XX`. Rack decodes
> query strings and cookies with `decode_www_form_component` ([Rack::QueryParser](...) and
> [Rack::Utils.unescape](...) in Rack 3.2.9), and Rails decodes query parameters and URL-encoded form fields with
> it ([ActionDispatch::QueryParser, Rails 8.1.4.1](...)).
>
> The shared helper now yields the checked copy to `CGI.unescape` or `CGI.unescapeURIComponent`, which decode in
> one pass in C (in Java on JRuby). Results have the same class, bytes and encoding as before. Where cgi/escape
> has no native `unescapeURIComponent` (cgi before 0.3.3, TruffleRuby), both methods keep the `gsub`. uri now
> requires cgi/escape, which every supported Ruby ships.
>
> (table: four rows) With YJIT, and with ZJIT on Ruby master, time per call drops by 23% to 80%. Each call
> allocates 2 or 3 objects instead of 4 to 8.

## Optional

Each of these keeps behaviour: `v-polish` applies O1 to O4 to the head and `v-native` includes them; both pass
every row of the table above.

`decode_www_form_component` says "Encoding::ASCII-8BIT (using String#b)" too. The two new lines introduce the
other name for the same object.

```diff
-    _decode_uri_component(str, enc) {|bytes| CGI.unescape(bytes, Encoding::BINARY) }
+    _decode_uri_component(str, enc) {|bytes| CGI.unescape(bytes, Encoding::ASCII_8BIT) }
```

**O2. The conditional as ruby/erb lays it out** (only if the head's shape stays; the single check already has it).
"Only where cgi/escape decodes in C or Java (cgi 0.3.3 and later)." has no subject and says where, not why; the
`# :nodoc:` is not needed, since RDoc keeps the first definition's documentation (tried with 7.0.4: `ri` output
identical). ERB puts the reason on the `else`:

```diff
-  # Only where cgi/escape decodes in C or Java (cgi 0.3.3 and later).

     end
-  else
-    def self.decode_uri_component(str, enc=Encoding::UTF_8) # :nodoc:
+  else # cgi before 0.3.3, or a CGI.unescapeURIComponent written in Ruby
+    def self.decode_uri_component(str, enc=Encoding::UTF_8)
       _decode_uri_component(str, enc) {|bytes| bytes.gsub(/%\h\h/, TBLDECWWWCOMP_) }

   end
```

**O3. The helper's comment.** "Returns a string decoded by the block from the bytes of the given \URL-encoded
string +str+" takes two readings. It also no longer mentions `enc`.

```diff
-  # Returns a string decoded by the block from the bytes of the given
-  # \URL-encoded string +str+.
+  # Returns the given \URL-encoded string +str+ decoded in encoding +enc+;
+  # the block decodes its bytes.
```

**O4. Tests: one assertion form, four lines fewer.**

* `assert_instance_of(String, URI.decode_uri_component(Class.new(String).new("a")))` instead of
  `assert_equal(String, ....class)`: it is the assertion for this and prints the object on failure.
* The two `%zz` assertions are never the only failing assertion for any mutant: `x%a_` already fails for the
  `\w\w` mutant, and `%zz` does not fail for the `\h?\h` one (`rework/tests/mutants_by_assert.txt`; astra said the
  same).
* The two GB18030 assertions pin a TruffleRuby crash inside cgi's Ruby `unescape`. Without them the "no `b` copy"
  mutant still fails on MRI through the subclass assertion, and with the single check that Ruby code never runs. A
  reader cannot tell what the four bytes are for, and a comment to explain them would be the kind DECISIONS rules
  out.

With these gone (8 added test lines instead of 14), every mutant in `mutants.rb` still fails at least one
assertion on at least one of MRI 4.0.9, 4.0.9 without the C decoder, and TruffleRuby 40: all 14 for the single
check, and the 12 that apply to the head's code (`logs/mutants-v-native.txt`, `logs/mutants-v-polish.txt`). The
mixed-case, `%FF` and empty
assertions stay: the first two are the only ones that catch an upper-case-only fallback and a decoder that picks
its own result encoding.

**O5. Commit message.** Apart from finding 2 it is accurate; I checked the cgi tags (C `unescapeURIComponent`
absent in v0.3.2, present in v0.3.3; Java absent in v0.4.0, present in v0.4.1). It is long for the change, and
with the single check two of its qualifications go. A version for that shape:

```
Decode URI components with cgi/escape

URI.decode_www_form_component and URI.decode_uri_component copy the
String with `b` and then run `gsub` with a regexp and a Hash, which
costs a match, a substring and a Hash lookup for every "+" and "%XX".
Rack and Rails decode query strings, URL-encoded form fields and
cookies through decode_www_form_component.

The shared _decode_uri_component keeps the lone-"%" check, the `b` copy
and the final force_encoding, and now takes the decoding step as a
block: CGI.unescape for decode_www_form_component, and
CGI.unescapeURIComponent, which keeps "+", for decode_uri_component.
Both decode the BINARY copy in one pass, so the result has the same
class, bytes and encoding as before.

cgi/escape has unescapeURIComponent in C since cgi 0.3.3 (Ruby 3.1.3)
and in Java since 0.4.1. Elsewhere both methods keep the `gsub`: on
TruffleRuby cgi/escape is written in Ruby, where CGI.unescape is slower
than the `gsub` and String#b keeps a String subclass.

URI.decode_www_form keeps its `gsub!`: it leaves a lone "%" as is, and
for the plain keys and values most forms have, CGI.unescape would
return a new String where `gsub!` changes nothing.
```

"slower than the `gsub`" rests on the TruffleRuby runs above; rerun them on the cohort the rules ask for, or drop
the clause and keep the `String#b` reason alone.

**O6. Names.** `_decode_uri_component(str, enc) {|bytes| ... }` is fine. `bytes` could be read as `String#bytes`
(an Array), but it says what the block gets better than `s` would. No change suggested.

## The brief's questions

* **Simplest, most readable shape?** The block helper is right: validation, copy and encoding stay in one place
  and each caller names its decoder. What is not simplest is the half-applied check (finding 1). I could not find
  a shape that uses cgi/escape for both methods, falls back where it is not native, and defines each method once
  without adding a layer (a second pair of private methods, or a module that stands in for CGI) or a per-call
  branch; the two-branch form above is the plainest of the ones that work.
* **Is the availability check clean and decided once?** It runs once, at load, and `source_location` is the
  right test. It decides for one of the two decoders only.
* **Names, comments, test layout, commit message?** O1 to O5.
* **Other callers that should share the helper?** None.
  * `URI.decode_www_form` (`common.rb:649`, `651`) leaves a lone `%` as it is and scrubs afterwards; the earlier
    reviews already showed that `CGI.unescape` costs objects on plain fields there.
  * `URI::MailTo#check_to` (`mailto.rb:182`) decodes a checked address in place and in its own encoding, with no
    `b` and no result encoding; open ruby/uri PRs touch MailTo.
  * `URI::Generic#decoded_user` and `#decoded_password` call `decode_uri_component`, and `MailTo#to_mailtext`
    calls `decode_www_form_component`; they gain without a change.
  * `URI::RFC2396_Parser#unescape` has another contract: a caller-supplied regexp, no error for a lone `%`, the
    input's encoding kept (US-ASCII becomes UTF-8) and an ArgumentError for invalid byte sequences. Against
    `CGI.unescapeURIComponent(str, str.encoding)` it differs in 24,778 of 100,000 random cases
    (`rfc2396_lead.rb`, `logs/rfc2396-unescape-lead.txt`). Not this helper and not this PR.
* **Anything unnecessary in the body?** Finding 3.

## Leads, outside this PR

Recorded here only; nothing was posted.

* TruffleRuby 40.0.0: `String#tr` takes about 600 ns on a five-byte string, and `String#b` returns the subclass
  for a String subclass, unlike CRuby. Both are behind the two TruffleRuby special cases in this change.
* cgi's Ruby `CGI.unescape` runs `tr` on every call, also when the string has no `+`.

## Limits

* Timing here is wall time on an 8-core orb with one process per pair of cores. It supports "several times
  slower" and "no visible difference", not percentages for a body.
* The RubyGems vendoring effect is read from source, not run.
* I did not rerun the head on 4.0.10, master, YJIT, ZJIT, 2.5.9, 3.1.2, 3.4.12 or JRuby 10.1, and the single-check
  variant has not run on those either. It needs the full matrix and both reviewers before it could become the
  head.
* The citation check of Rack and Rails (stars, downloads, permalinks) was not repeated; the links in the body are
  unchanged from the reviewed draft.
