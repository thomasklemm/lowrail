## Demonstrated differences

These require Ruby-level hooks or special objects; no request-bytes-only exploit was demonstrated.

1. **The new guard invokes user code after validation.** With the following input, base returns `"aA b"`
   without changing the input; head returns `"%zz"` and changes the input to `"%zz"`. Both native CGI and the
   pure-Ruby fallback reproduce it. The claimed invalid-percent boundary is therefore not exact.

   ```ruby
   s = +"a%41+b"
   def s.encoding
     replace("%zz")
     Encoding::UTF_8
   end
   URI.decode_www_form_component(s)
   ```

2. **Input hooks and error paths change.** Public/private singleton `b` raising an exception is honored by base,
   ignored by head. Public/private singleton `encoding` or `instance_of?` raising is ignored by base, invoked by
   head. `extend`/singleton-class `prepend` versions of `b` returning `"extended"`/`"prepended"`, or a `b` returning
   frozen `"frozen"`, change base's result; head instead returns `"aA b"`. On pure-Ruby CGI, singleton `tr` is a
   further newly invoked method: the raising/private variants turn base's success into RuntimeError/NoMethodError.
3. **The subclass/other-object claim has counterexamples.** A String subclass with `b` returning `"subclass"` and
   `instance_of?(String)` returning true produces `"subclass"` on base, `"aA b"` on head. A BasicObject implementing
   both `to_str` and `b` as `"a%41+b"` succeeds on base, raises NoMethodError for `instance_of?` on head. This is
   more than the builder's already recorded BasicObject error-message difference.
4. **New CGI dispatch and removed URI helper dispatch are observable.** A CGI singleton-class prepend returning
   `"intercepted"` leaves base's `"aA b"` unchanged but becomes head's result. A singleton CGI.unescape returning a
   frozen `"intercepted"` instead makes head raise FrozenError. A prepend overriding URI's private
   `_decode_uri_component` returns `"intercepted"` on base and is bypassed on head. These are explicit override
   boundary results, not a claim that such patches exist in Rails or Rack. Public URI decoder wrapping with `super`
   remains effective on both.

The item's earlier "b not called; others unchanged" and blanket acceptance of that boundary are not supported by
these runs. DECISIONS exempts escaping from the normal override-boundary allowances. Resolve the boundaries before
approval; do not infer a need for an expanding set of guards from this report. Mark the item risky because this is
request decoding. No added upstream code comments need removal.
