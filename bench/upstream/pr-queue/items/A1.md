# Check the owner conditions only when an association scope was merged

Since #59825 and #59836, loading an association builds the differences between its where clauses before and after
the association scope is merged, so that `keep_owner_conditions` can tell whether the scope removed the conditions
tying the records to the owner. It builds them for every association, including the common case of one without a
scope, where nothing can be removed: `author.posts` builds five `WhereClause` differences, and `joins(:posts)` one.

This keeps the where clauses and computes the differences only when a scope was merged. SQL, records and
deprecation warnings stay the same, with `association_scope_keeps_owner_conditions` on and off.

Objects and Callgrind instructions per call, Ruby 4.0.9, no JIT:

| | Objects, main | Objects, branch | Instructions, main | Instructions, branch | Change |
| --- | ---: | ---: | ---: | ---: | ---: |
| `author.posts` | 121 | 111 | 720,039 | 706,950 | −1.8% |
| `author.profile` | 101 | 91 | 593,753 | 580,714 | −2.2% |

With YJIT the same calls run 1.2% to 4.1% fewer instructions. An association with a scope is unchanged.
