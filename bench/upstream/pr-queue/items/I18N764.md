# Avoid wrapping scalar defaults in an Array in Fallbacks#extract_non_symbol_default!

#### Summary

`Backend::Fallbacks#translate` calls `extract_non_symbol_default!` when `options[:default]` is truthy. It starts with `[options[:default]].flatten`, which allocates a wrapper Array and a flattened copy even when the default is a single Symbol, String, Hash or Integer.

For scalar defaults, this PR avoids those Arrays: a Symbol returns early; other scalar defaults are returned with `options[:default] = []`. Array defaults keep `[default].flatten`. Translation calls with nil or false defaults skip extraction as before.

A non-Array default's custom `to_ary` coercion is no longer invoked; that coercion is outside the documented default contract.

#### Benchmark

The original guarded version was measured on Ruby 4.0.7, objects allocated per call with `I18n::Backend::Fallbacks` included (same with and without YJIT):

```
                                 before   after
Array default                      21  ->  21
String default                     23  ->  21
Symbol default                     29  ->  27
Hash default                       22  ->  20
Integer default                    14  ->  12
```

Across 20 open-source Rails apps (251 request, job and mailer workloads), that version removed 0.3% of all allocated objects; most of it was in apps that pass Integer defaults or translate heavily on one dashboard. These app measurements have not been rerun for the simplified guard.

#### Testing

Added a test that nested Array defaults still flatten without changing the given Array. The test suite passes (1,608 runs, 2,676 assertions). The retained tests protect existing behavior and also pass on master; independent mutation checks reject removing flattening or clearing of scalar defaults. Fresh allocation checks reproduce String defaults at 23 → 21 objects per call and Symbol defaults at 29 → 27.
