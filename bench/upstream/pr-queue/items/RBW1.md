# Add a blog benchmark that writes

The Rails benchmarks here mostly read: in their timed iterations none of them submits a form, fails a validation, or runs after-commit callbacks.

This adds `blog`, the app built by the [`create-blog`](https://github.com/roundhouse-rb/roundhouse/blob/aa60799f53b36084c6311ffcda8f14e746eebf79/scripts/create-blog) script from Sam Ruby's [Roundhouse](https://github.com/roundhouse-rb/roundhouse) (MIT or Apache-2.0): a `rails new --css tailwind` app on Rails 8.1.4.1 with Article and Comment scaffolds, validations and Turbo broadcasts, on the default SQLite, Solid Cache, Queue and Cable. Each iteration makes about 420 in-process requests (reads, creates, updates, deletes, comments and a create that fails with 422) with real CSRF tokens, checks every response, and rolls back one transaction per database at the end, as Rails tests do. It works on Rails 8.1 and main.

It runs code the others don't: a small busy loop in `save` and `destroy` adds 2.3% to blog's instructions and never runs in railsbench's or lobsters' timed iterations. From Rails 8.1.4.1 to main, its reads take about a tenth fewer instructions while creates and updates don't get faster.

An iteration takes about 2 s in the interpreter and about 1 s with YJIT or ZJIT. The README lists every change to the generated app and what the rollback leaves out.

Would a write workload like this be welcome? Happy to reshape it.
