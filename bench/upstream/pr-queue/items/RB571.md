# Run lobsters with a fixed clock

This fixes lobsters' clock at 2026-07-01 12:00 UTC, so its work per iteration no longer depends on the date it runs. #572 is an alternative that fixes the clock near the fixture's dates, so the 16 time-filtered requests render stories; merge one of the two.

lobsters runs in US Central time. On main, when a lookback such as `70.days.ago` crosses a DST change, ActiveSupport looks up the zone period again: 1,476 extra lookups per pass on 2026-11-05, and none in July. On Dec 25 and Jun 28 the logo changes too. With a fixed reference instant, every lookback and the logo come out the same on every run.

Objects allocated per iteration, as I measured them on Ruby 4.0.9 (default harness; the real clock moved by libfaketime, mean of 3 iterations after 1 warmup):

| | 2026-11-05 | 2026-12-25 | 2027-03-20 | 2027-06-28 | spread |
| --- | ---: | ---: | ---: | ---: | ---: |
| main | 657,758 | 657,025 | 657,811 | 648,912 | 1.37% |
| this PR | 648,831 | 648,883 | 648,864 | 648,871 | 0.01% |

All 114 response bodies of a pass after warmup are byte-identical between processes run on 2026-11-05 and 2027-01-20, apart from CSRF tokens. The headers differ only in the session cookie, ETag, X-Request-Id and X-Runtime.

Only `Time.now` is fixed, and only during boot and the benchmark block; the harness keeps the real clock. `Date.today` and `DateTime.now` stay live, and lobsters doesn't call them during the benchmark. Cache entries and the session don't age, so they don't expire. `TRACK_AR_TIME` now uses the monotonic clock.

This is a one-time step in lobsters' history: about 1.35% fewer objects than on dates whose lookbacks cross a DST change (roughly November to January and mid-March to mid-June), and no change on other dates.
