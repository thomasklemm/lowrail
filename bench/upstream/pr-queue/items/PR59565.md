# Hint at casts when PostgreSQL rejects a bind parameter after a type name or IS

Since #58427 (unreleased), array-form `find_by_sql` and `count_by_sql` use bind parameters with prepared statements on. PostgreSQL then rejects `find_by_sql(["SELECT * FROM events WHERE starts_on > DATE :d", d: date])` with `syntax error at or near "$1"`, though it works on 8.1: `DATE` requires a literal, not a placeholder.

In #55439, byroot invited a PR to augment the error for common cases. This adds a hint for placeholders after common type names or `IS`: cast the placeholder (`$1::date`); for `IS`, use `IS NOT DISTINCT FROM` (`IS DISTINCT FROM` for `IS NOT`); or interpolate with `sanitize_sql_array`. It preserves the exception class and original message and checks only PostgreSQL's reported error position. Other errors and successful queries are unchanged.
