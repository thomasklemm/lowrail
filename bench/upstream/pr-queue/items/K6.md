# Build `button_to` params with `tag`, as `token_tag` does

Follow-up to #50312. Since `button_to` is built on `form_tag`, each entry of `params:` goes through `hidden_field_tag` and `text_field_tag`, which compute an `id` with `sanitize_to_id` only for `id: nil` to drop it, and merge and stringify the options for every field. With 20 params, a `button_to` call now runs 45% more instructions than before #50312.

This builds each field with `tag`, as #50312's own `token_tag` and `method_tag` do and as `button_to` does in 8.1. The fields render the same: `type`, `name`, `value` and `autocomplete`, in that order, without an `id`. Since `button_to` reads `remove_hidden_field_autocomplete` itself again, a test now covers that setting.

Callgrind instructions and objects per call, Ruby 4.0.9, no JIT:

| `button_to` with | main | this change |
|---|---:|---:|
| 1 param | 230,504 (45) | 203,592 (39) |
| 20 params | 1,873,523 (368) | 1,326,369 (248) |
| 2,000 params | 174,274,877 (34,028) | 119,388,370 (22,028) |
| one 1 MB param value | 10,846,738 (45) | 10,849,004 (39) |

That puts 20 params back within 3% of before #50312. With YJIT: 1 param −14%, 20 params −32%, 2,000 params −34%. A second checkout of main moved by at most 0.22%.
