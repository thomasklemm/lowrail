# Allocate less per field in `text_field_tag` and `tag`

Follow-up to #50312. Since `button_to` is built on `form_tag`, each param goes through `hidden_field_tag(name, value, id: nil)` and `text_field_tag`, which computed an id with `sanitize_to_id` only for `id: nil` to drop it.

`text_field_tag` now computes the id only when none is given, so `button_to` keeps calling `hidden_field_tag`. The shared helpers also avoid two intermediate strings: `sanitize_to_id` replaces characters in its first copy instead of making a second, and `tag` freezes its string before `html_safe`, as `content_tag_string` and `self_closing_tag_string` already do.

The output is the same for every name that rendered before. Since the unused id is no longer computed, a name it can't convert, such as one with invalid UTF-8, now renders when an `id` is given instead of raising.

```ruby
require "active_support/all"
require "action_view"
require "benchmark/ips"

ActionView::Helpers::NavigationHelper.button_to_generates_button_tag = true
ActionView::Base.remove_hidden_field_autocomplete = true

view = ActionView::Base.empty
one = { "key" => "value" }
two = { "key" => "value", "other" => "value" }

Benchmark.ips do |x|
  x.report("button_to, 1 param") { view.button_to("Save", "/posts", params: one) }
  x.report("button_to, 2 params") { view.button_to("Save", "/posts", params: two) }
end
```
