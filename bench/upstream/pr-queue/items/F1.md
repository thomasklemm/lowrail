# Return same-object ar_table hits without calling ar_equal

Small-Hash lookups cost more on master than on 4.0. Since #18222, GCC compiles `ar_find_entry_hint` as its own function, which saves registers for its slow-path loop on every call; since #18476, `ar_equal` checks the identity flag and calls `rb_any_cmp` out of line. So a Symbol hit makes three calls to learn that the key is the object already in the slot.

```ruby
h = {a: 1, b: 2, c: 3}
i = 0
while i < 20_000_000; h[:b]; i += 1; end
```

This keeps the SWAR search and the identity hashes, and returns the first matching slot at once when it holds the key itself: an object is equal to itself for `rb_any_cmp` and in an identity hash, and no Ruby code runs there. Other cases run the previous code, now in `ar_find_entry_hint_slow`.

Callgrind instructions per iteration of such loops, x86-64, GCC 14 `-O3`, no JIT:

| | 4.0.9 | master | this PR |
|---|---:|---:|---:|
| `h[:b]` above | 274 | 320 | 281 |
| 8 Symbol keys, first / last key | 266 / 322 | 320 / 320 | 281 / 281 |
| 8 Symbol keys, miss | 333 | 313 | 300 |
| equal String key, another object | 502 | 539 | 552 |

Per lookup in the loop above: 10.5 ns on 4.0.9, 13.1 ns on master, 10.4 ns with this PR. Larger Hashes were checked and are unchanged.
