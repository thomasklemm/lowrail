# Return same-object ar_table hits without calling ar_equal

Looking up a key in a small Hash costs more on master than on 4.0. Since #18222, `ar_find_entry_hint` is a separate function that saves registers for its slow-path loop on every call, and since #18476, `ar_equal` checks the identity flag and then calls `rb_any_cmp` out of line. So a hit on a Symbol key makes three calls to learn that the key is the object already stored in the slot.

```ruby
h = {a: 1, b: 2, c: 3}
i = 0
while i < 20_000_000; h[:b]; i += 1; end
```

This keeps the SWAR search and the identity hashes, and returns the first matching slot right away when it holds the key itself. An object is equal to itself for `rb_any_cmp` and in an identity hash, and no Ruby code runs on that path, so the result is the same. Every other case runs the previous code, now in `ar_find_entry_hint_slow`.

Callgrind instructions per loop iteration with one lookup, x86-64, GCC 14 `-O3`, no JIT:

| | 4.0.9 | master | this PR |
|---|---:|---:|---:|
| `h[:b]` above | 287 | 333 | 294 |
| `benchmark/hash_ar_aref.yml` keys, first / last hit | 279 / 335 | 333 / 333 | 294 / 294 |
| `benchmark/hash_ar_aref.yml` miss | 346 | 326 | 313 |
| `{a: v, b: v, c: v}` | 917 | 1,168 | 1,084 |
| String key, equal but not the same object | 515 | 552 | 565 |

The loop above takes 10.4 ns per lookup instead of 13.1 ns (4.0.9: 10.5 ns). On ruby-bench, railsbench runs 0.4% fewer instructions per iteration without JIT and 0.6% fewer with YJIT. Larger Hashes, which use an st_table, were checked and are unchanged.
