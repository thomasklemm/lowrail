# [Fix #471] Preserve RedundantStringChars autocorrection boundaries

Fixes #471.

This fixes result and error boundaries in `Performance/RedundantStringChars` autocorrection. Range slicing now uses `&.chars`, so an out-of-bounds result stays `nil`. An integer `slice` stays a String instead of becoming an Array. `first` and `take` are corrected only for a literal non-negative count, so a negative count still raises `ArgumentError`. Index arguments whose type cannot be inferred are left alone.

The cop is also marked `Safe: false`: a static cop cannot establish that its receiver is a plain String. With Rails, `"abc".html_safe.chars.slice(1)` returns a plain `String` with `html_safe? == false`, but direct indexing of that buffer returns an `ActiveSupport::SafeBuffer` with `html_safe? == true`. Rewriting it can silently make a substring HTML-safe.
