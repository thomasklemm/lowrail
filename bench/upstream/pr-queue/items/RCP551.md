# [Fix #471] Preserve RedundantStringChars autocorrection boundaries

Fixes #471.

Preserve the result and error boundaries of `Performance/RedundantStringChars` autocorrection:

- Use `&.chars` after range slicing so an out-of-bounds result stays `nil`.
- Keep integer `slice` results as strings rather than converting them to arrays.
- Take a count as `[0, count].chars`, so a negative count raises instead of silently dropping the last characters as `[0...count]` did. Skip index arguments whose type cannot be inferred.

For example:

```ruby
str.chars[40..80]  # => str[40..80]&.chars
str.chars.slice(1) # => str[1]
str.chars.first(2) # => str[0, 2].chars
```

The cop is also marked `Safe: false`: a static cop cannot establish that its receiver is a plain String. With Rails, `"abc".html_safe.chars.slice(1)` returns a plain `String` with `html_safe? == false`, but direct indexing of that buffer returns an `ActiveSupport::SafeBuffer` with `html_safe? == true`. Rewriting it can silently make a substring HTML-safe.
