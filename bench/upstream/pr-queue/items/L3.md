# Build attribute Hashes without copying the lazy row

Since #59141, `attributes_for_database` and `attributes_before_type_cast` on a loaded record copy all of its attributes into a new `IndexedRow::Mutable` on every call, only to turn that row into a Hash. `Marshal.dump` of a record and the MessagePack cache coder call `attributes_for_database` once per record.

This builds both Hashes straight from the attributes the set already built, in the order of its indexes. The same method runs on the same attributes, so the Hashes and the record afterwards are unchanged. Reading the values from the row instead, as `#to_hash` does, would skip building the attributes but would not be the same: an encrypted attribute would dump a new ciphertext on every call.

Callgrind instructions and objects per call, Ruby 4.0.9, no JIT, a loaded 30-column record:

| | main | this change |
|---|---:|---:|
| `Marshal.dump(record)` | 362,232 (28) | 306,514 (25) |
| MessagePack dump | 204,466 (23) | 149,102 (20) |
| `attributes_for_database` | 161,843 (4) | 106,307 (1) |
| `attributes_before_type_cast` | 123,862 (4) | 68,839 (1) |

A second checkout of main moved by at most 0.26%. The gain holds from 6 to 300 columns. With YJIT: `Marshal.dump` −16%, MessagePack dump −35% (a second checkout of main within 0.41%).
