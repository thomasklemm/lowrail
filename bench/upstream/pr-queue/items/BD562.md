# Reuse the frozen zero when converting Integer 0 to BigDecimal

Converting Integer `0` to a BigDecimal allocates a new zero every time. That happens in `x > 0`, `x <=> 0`, `x == 0`, `x + 0`, `x * 0`, `0 + x` (through `coerce`), `BigDecimal(0)` and `0.to_d`. This PR returns the existing frozen positive zero instead, as the Float `0.0` conversion already does.

BigDecimal objects are frozen, and no caller of the Integer conversion modifies a zero result. Repeated conversions now share identity: `BigDecimal(0).equal?(BigDecimal(0))` is true, as `BigDecimal(0.0).equal?(BigDecimal(0.0))` already is.

Active Record compares every decimal value it casts with Integer zero (`value <=> 0` in `ActiveModel::Type::Helpers::Numeric#cast`), so this applies once per decimal value it loads or binds.

Objects allocated per operation, Ruby 4.0, no JIT:

| Operation | Before | After |
| --- | ---: | ---: |
| `x > 0`, `x <=> 0`, `x == 0`, `BigDecimal(0)`, `0.to_d` | 1 | 0 |
| `x + 0`, `x - 0`, `x * 0`, `0 < x` | 2 | 1 |
| `0 + x` | 3 | 2 |
| 2,000 Active Record decimal deserializations | 6,001 | 4,001 |
| A PostgreSQL result of 1,000 rows with two numeric columns | 12,024 | 10,024 |
