# Cache the modulepreload tags of an entry point and build them with fewer objects

`javascript_importmap_tags` is in the layout of every new Rails app, so it runs on every HTML page. It builds a `<link rel="modulepreload">` tag for every preloaded module, seven in a new app and dozens once an app has its own Stimulus controllers, although without a CSP nonce the tags are the same on every page. While profiling a new app's requests, I found that building them is about a tenth of the instructions of a request for a page with an empty view.

The packages behind the tags are already cached in the map per entry point. When the page has no CSP nonce, the tags now go into the same cache, so they're cleared together when a pin changes or the cache sweeper runs. Each call returns a copy, so appending to the result doesn't change the next page.

With a nonce, the tags are still built on every call, but each one directly in the block, without a `[path, options]` pair and an options Hash per module. That is two fewer objects per module, at the same speed within noise.

```ruby
# bin/rails runner in a new app; NONCE=1 adds a CSP nonce
require "benchmark/ips"

env = Rack::MockRequest.env_for("https://localhost/")
if ENV["NONCE"]
  env["action_dispatch.content_security_policy"] = ActionDispatch::ContentSecurityPolicy.new { |policy| policy.script_src :self }
  env["action_dispatch.content_security_policy_nonce_generator"] = ->(request) { SecureRandom.base64(16) }
  env["action_dispatch.content_security_policy_nonce_directives"] = %w[script-src]
end

controller = ApplicationController.new
controller.request = ActionDispatch::Request.new(env)
view = controller.view_context

Benchmark.ips do |x|
  x.report("javascript_importmap_tags") { view.javascript_importmap_tags }
end
```
