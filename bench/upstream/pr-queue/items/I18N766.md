# Check for Fiber storage once in I18n.config

Since #731 and #739, `I18n.config` checks `Fiber.respond_to?(:[])` on every call, so that Rubies without Fiber storage (3.1, JRuby 9.4) keep using thread variables. A translation reads the config about five times, so removing this check saves about 3% of the instructions of a simple `I18n.t`.

I record in a private constant whether `Fiber[]` existed when i18n loaded, and `I18n.config`, `writable_config` and `config=` only check again when it didn't. Core Fiber storage is available from Ruby 3.2. On Rubies without it, every call still checks, so a `Fiber[]` defined later (for example by the fiber-storage gem) is still picked up.

Callgrind instructions per call with `I18n::Backend::Fallbacks` included, Ruby 4.0, no JIT:

| Call | Before | After |
| --- | ---: | ---: |
| `I18n.t(:hello)` | 53,811 | 52,016 |
| `I18n.t(:greet, name:)` | 81,039 | 78,874 |
| `I18n.t(:missing, default: "x")` | 73,772 | 72,075 |
