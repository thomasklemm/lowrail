# Escape a single cookie value without wrapping it in an Array

`Rack::Utils.set_cookie_header` wraps a cookie value that is not an Array in a one-element Array, maps it through `escape` and joins the result. So every `Set-Cookie` header with a single value, which is the usual case, builds two Arrays and a String that are thrown away. With the stock `escape`, the header is the same for every value. Only unusual code could notice: an `escape` override that returns a non-String is now converted with `to_s` (`join` tried `to_str` and `to_ary` first), a non-String key's `to_s` now runs after the value is escaped instead of before, and `Array#map` no longer appears in `escape`'s backtrace.

Callgrind instructions, time and objects per call:

| One call | Before | After |
| --- | ---: | ---: |
| `set_cookie_header("k", "value")`, Ruby 4.0 | 15.8k instructions, 1.92 µs, 12 objects | 13.6k, 1.59 µs, 9 objects |
| same, YJIT | 12.4k instructions, 1.61 µs | 10.8k, 1.39 µs |
| same, Ruby master with ZJIT | 11.1k instructions | 9.5k |
| session cookie with `path`, `httponly`, `same_site`, Ruby 4.0 | 35.7k instructions, 19 objects | 33.5k, 16 objects |

Rails writes its session cookie and every other cookie through this method; in 17 of the 20 open-source Rails apps I profile, requests write 0.6 to 2 cookies on average.
