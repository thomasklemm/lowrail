# Resolve nested serializers returned by prop types

## Summary

Apply `to_inertia` consistently to objects nested in a Hash or Array returned by a prop type, as already happens for directly returned serializers and closure results. Previously these nested objects used Rails' default JSON serialization, which can include instance variables omitted by `to_inertia`.

Resolve these nested values through the existing prop resolver. Preserve partial `only`/`except` selection, Always data, deferred/once/merge metadata, array positions, rescue handling, and single evaluation. Keep the established behavior of directly returned serializers and closure results, except that a `rescue: true` prop now also rescues an error raised while serializing a directly returned serializer's projection instead of raising during rendering. Plain container results retain their existing fast path.

## Regression coverage

Request specs cover initial HTML and Inertia JSON, deferred/optional partial responses, child filters, rescue of `to_inertia` and later `as_json` errors, metadata, and consecutive requests with different viewers. Resolver specs additionally cover unrequested Always containers with executable children, array placeholders, and selected merge children.

## Checks

On current master with Ruby 4.0.7 / Rails 8.1.4.1, Ruby 3.4.12 / Rails 8.0.5.2 and Ruby 3.2.11 / Rails 7.1.6:

- `bundle exec rspec --tag ~type:generator`: 1102, 1098 and 1098 examples, 0 failures.
- `bundle exec rake test`: 61 runs, 107 assertions, 0 failures/errors/skips.
- `bundle exec rubocop`: 197 files, no offenses.

The nine new HTTP regression tests fail on the unchanged base and pass with the fix. The generator suite is separate in upstream CI and is unchanged.

### Conflict resolution and guard

- The merged `each` loop, `plain_leaves` fast path, explicit return and BaseProp-only predicate/rescue checks
  remain. `plain_leaf?` excludes every Hash, Array, Proc, BaseProp and serializer, including subclasses, so it
  cannot skip the executable children or nested serializers under review. DevTools disables this shortcut.
- The explicit-loop `needs_transform?` implementation from the configuration/scan change is byte-identical
  to master's. The new `filter_nested_props` flag propagates across the three existing traversal methods;
  unrequested Always data remains included while executable children obey partial selection.
- The simplified guard is exact for the documented evaluator contract: Procs and serialized results already
  enter; nonempty Hashes and Arrays already left through the earlier container branches; ordinary leaves are
  returned unchanged by the evaluator and cannot produce a newly transformable container. Empty Hashes need
  no transformation. Removing the BaseProp conjunction adds no executable/container case.
- Reran the original 22 × 6 × 2 probe: the same 114 changed rows on both bases, the same 10 predicate-data
  corrections after applying the fix, both overlapping rows retain projection and predicate-as-data behavior,
