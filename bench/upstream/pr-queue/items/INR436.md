# Resolve nested serializers returned by prop types

## Summary

Apply `to_inertia` consistently to objects nested in a Hash or Array returned by a prop type, as already happens for directly returned serializers and closure results. Previously these nested objects used Rails' default JSON serialization, which can include instance variables omitted by `to_inertia`.

Resolve these nested values through the existing prop resolver. Preserve partial `only`/`except` selection, Always data, deferred/once/merge metadata, array positions, rescue handling, and single evaluation. Keep the established behavior of directly returned serializers and closure results. Plain container results retain their existing fast path.

## Regression coverage

Request specs cover initial HTML and Inertia JSON, deferred/optional partial responses, child filters, rescue, metadata, and consecutive requests with different viewers. Resolver specs additionally cover unrequested Always containers with executable children, array placeholders, and selected merge children.

## Checks

On current master with Ruby 4.0.7 / Rails 8.1.4.1, Ruby 3.4.12 / Rails 8.0.5.2 and Ruby 3.2.11 / Rails 7.1.6:

- `bundle exec rspec --tag ~type:generator`: 1100, 1096 and 1096 examples, 0 failures.
- `bundle exec rake test`: 61 runs, 107 assertions, 0 failures/errors/skips.
- `bundle exec rubocop`: 197 files, no offenses.

The seven new HTTP regression tests fail on the unchanged base and pass with the fix. The generator suite is separate in upstream CI and is unchanged.
