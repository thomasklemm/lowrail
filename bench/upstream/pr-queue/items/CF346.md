# Migrate background jobs from Resque to Solid Queue

Replace Resque and resque-pool with Solid Queue. Resque payloads are not copied: operators must drain the old queues before deploying. Solid Queue uses its own SQLite database at `storage/db/production_queue.sqlite3`; normal `db:prepare` prepares it before services start.

The default is one worker process with three threads, with `JOB_CONCURRENCY` adding processes and a separate queue connection pool of five. Queue storage retains WAL auto-checkpointing, and each forked worker, dispatcher and scheduler starts its own checkpoint contender. The performance-load environment gets the same queue configuration. Posting a message batches its jobs into one queue transaction. The shutdown timeout gives a running job eight seconds of Docker's ten-second stop window. Redis remains required for Action Cable and Rails cache until their separate migrations.

The [upgrade guide](https://github.com/thomasklemm/once-campfire/blob/3703ab13b4c4789dbf6130546e8d16ea21b43181/docs/upgrades/solid-queue.md) describes draining Resque before switching backends. Backups still snapshot only the primary database; the archive excludes the queue database, and restore deletes any queue database left in the volume. All pending jobs are lost on restore, including unfinished deletion work, not just notifications and webhooks.

[A posting benchmark in the discussion](https://github.com/basecamp/once-campfire/pull/346#issuecomment-6114638577) found lower throughput than Resque. More worker processes kept up with the queued work but reduced posting throughput further. [Batching the per-post enqueues](https://github.com/basecamp/once-campfire/pull/346#issuecomment-6418720495) improved throughput in a separate comparison; it does not establish a speedup over Resque.

[Queued jobs survive a container restart](https://github.com/basecamp/once-campfire/pull/346#issuecomment-6387970909), unlike the old container-local Redis queue. A job interrupted while running is marked failed and must be retried by hand. This PR does not retry it; #417 adds a targeted retry policy.
