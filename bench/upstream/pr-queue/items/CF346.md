# Replace Resque with Solid Queue

Jobs move from Resque in the container's Redis to Solid Queue in its own SQLite database. That Redis doesn't persist (`save ""`), so today a restart or an update drops every queued job, such as the file purges of a room deletion. With Solid Queue they're still there when the container starts again; @namespaceMarcello's runs in this thread show it for `docker kill`, `docker stop` and an ONCE update.

The queue database is backed up and restored with the primary, so a room deletion or a banned user's content removal still queued at the backup runs after a restore. The worker runs three threads in one process, as Solid Queue's installer sets it up, with its own pool of five connections. Jobs still in Resque at the upgrade are lost, as on any restart today.
