# fix: hold transaction-level try locks until the transaction ends on Rails 8.2+

Fixes #149.

While running OpenProject's test suite on Rails main, I found that [a Rails change](https://github.com/rails/rails/commit/01e33f82f829b12273eb66e9fff80bbb36daf12b) made the internal `query_*` methods default to `materialize_transactions: false`. When the try lock is the first statement in a transaction, its `query_value(sql)` now runs before the lazy `BEGIN`, so `pg_try_advisory_xact_lock` is released when that statement ends. This passes `materialize_transactions: true` on the try path, behind the same `internal_exec_query` check as the blocking path, so Rails 8.1 and earlier are unchanged.

I'll keep this as a draft until the Rails 8.2 beta, since the change on Rails main may still move, and update it then.
