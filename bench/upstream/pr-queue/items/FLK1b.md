# Unpin the main pool the Ractor proxy pinned

While going through two months of Buildkite failures on main, I found that `AsynchronousQueriesTest#test_async_query_retries_connection_failure` fails in the sqlite3:ractor job for some seeds. On unpin, the Ractor connection proxy looked the main pool up again by name, role and pool token and unpinned nothing, so the writing pool stayed pinned for later tests. The proxy now unpins the main pool it pinned, as `ConnectionPool` itself does. The commit explains the cause.

Run together with the two tests that set it up, in random order, the async test failed in 15 of 120 runs before and in none after.
