# Find SQLite tables by any ASCII case of their name in the schema readers

Stacked on #59668, which should merge first; only the last commit (`63d1880397`) is new here.

2cb3daba96 batched the SQLite schema readers, which now match table names exactly. The previous pragma-based readers matched them the way SQLite does, ignoring ASCII case. So a model whose `table_name` is `"widgets"` can no longer read a table created as `Widgets`: `columns` and `primary_key` raise `StatementInvalid`, and indexes and foreign keys come back empty. ransack's [`context_spec.rb`](https://github.com/activerecord-hackery/ransack/blob/fbc3baf164da2a80435d5678a77924c66472f694/spec/ransack/active_record/context_spec.rb#L73-L81) hits this.

The readers now match with `COLLATE NOCASE`, which folds only ASCII, like SQLite identifiers, so `Ärger` and `ärger` stay two tables. A table read with a different ASCII-case spelling also gets its collations and auto-increment, which 8-1-stable lost. #59668's check that lets a temporary table or view hide a permanent one is now case-insensitive as well. #59672 (each index from its own schema) is stacked on this one.
