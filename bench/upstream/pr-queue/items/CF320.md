# Let bots send their key in an Authorization header

Bot API URLs carry the bot's key in the path (`/rooms/:id/:bot_key/messages`), and Thruster's access log writes the path in the clear, so every bot request leaves a working credential in the container log (#272).

Bots can now call `/rooms/:id/bot/messages` with `Authorization: Bearer <key>`, which keeps the key out of the URL. Pagination links follow the path the request used, the bots page shows the header form, and webhooks send the key-free path as `room.api_path` next to `room.path`. Paths with the key keep working as before, so existing bots are unaffected.

Fixes #272.
