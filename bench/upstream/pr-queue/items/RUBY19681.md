# ZJIT: Find caller-saved survivors without scanning every interval per CCall

This change halves the time ZJIT spends compiling one method with 2,000 or 4,000 calls.

`handle_caller_saved_regs()` filtered every interval at every C call to find the registers live across it, so its cost is the number of C calls times the number of intervals. This PR maps each register interval's live ranges onto the sorted C call positions once, with a binary search per range, into one flat table. Each C call reads its slice of that table; there is no intermediate Vec per C call, and the survivor buffers are reused. Survivors keep the same VRegId order, so the generated code is unchanged.

This is a stopgap; it doesn't split intervals.

Fixes Shopify/ruby#1065

`--zjit-stats` at `--zjit-call-threshold=2` for this script, which calls one method of N `s ^= o.hash` calls three times:

```ruby
n = Integer(ARGV[0])
src = +"def big(o)\n  s = 0\n"
n.times { src << "  s ^= o.hash\n" }
src << "  s\nend\n"
eval(src)
o = Object.new
3.times { big(o) }
```
