# Share message fragments between viewers and workers

Message fragments are keyed by content but also by viewer and session, in a per-worker memory store, so with many people reading a room each of them renders each message once per worker. This shares them through `Rails.cache` across viewers and workers, under a namespace of deployment, origin, mount path and locale.

A key reads the message, room, creator, body and boosts as stored, so SQL edits that skip timestamps still miss. Messages with attachments, mentions or in a direct room render fresh without costing their neighbours a hit. Complete responses and authorization snapshots stay per worker, in one bounded MemoryStore instead of the hand-rolled FIFO.

The last two commits are @namespaceMarcello's: keys from stored values, which also fixes a 500 for a body stored as invalid text. His [load run](https://github.com/basecamp/once-campfire/pull/350#issuecomment-6390359055) on an earlier head shows the effect with many viewers.
