# Use native shared fragments and simplify the local hot-path cache

Stacked on #345, which should merge first; [compare the fragment-cache changes](https://github.com/thomasklemm/once-campfire/compare/deps/solid-cache...perf/native-fragment-cache) separately.

This shares viewer-independent HTML fragments through Rails' collection caching and Solid Cache instead of rendering them once per viewer. Content-derived keys cover body, room, creator and boost inputs, including SQL edits without timestamp changes. Attachment, mention and direct-room messages render fresh without disabling collection hits for their neighbours. Detached and primary-transaction renders bypass shared fragments; JSON renders fresh, and direct sidebars preload participants.

Presentation caches are namespaced by deployment revision, signing key, URL origin, mount prefix and locale. Set an immutable `GIT_REVISION` to share across workers; unversioned builds get a boot-local namespace. Responses and authorization snapshots share a bounded per-worker `MemoryStore`, retaining access checks, admission limits, cold-render collapse and SQLite `data_version` validation. `CAMPFIRE_RESPONSE_CACHE_MB=0` disables it.

Collection-cached messages no longer write redundant nested fragments. This removes duplicate full-message caching, the custom fragment store and Jbuilder overrides.
