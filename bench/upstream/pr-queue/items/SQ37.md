# Bump the minimum supported SQLite version to 3.37.0

Since #52354 (Rails 8.0), [`data_source_sql`](https://github.com/rails/rails/blob/f785381cca8621772cba659ff93f825eb7f99942/activerecord/lib/active_record/connection_adapters/sqlite3/schema_statements.rb#L216-L225) reads `pragma_table_list`, which SQLite added in 3.37.0. [`check_version`](https://github.com/rails/rails/blob/f785381cca8621772cba659ff93f825eb7f99942/activerecord/lib/active_record/connection_adapters/sqlite3_adapter.rb#L518-L522) accepts 3.35.0 since #58284, so on SQLite 3.35 and 3.36 `table_exists?`, `tables`, the schema cache and migrations raise `no such table: pragma_table_list`, and with them `bin/rails db:prepare` and `Model.create!`.

This raises in `check_version` below 3.37.0, as #58284 did for `RETURNING`, so these versions fail at connect with a clear message instead. Only apps that build the `sqlite3` gem against an older system SQLite are affected, since the gem ships a current one.

## For Thomas

Rails reads the list of tables from a SQLite feature that only exists from 3.37 on, but its version check lets 3.35 and 3.36 through. On those versions nothing that touches the schema works: `db:prepare` and every model fail with "no such table: pragma_table_list". The change moves the version check to 3.37, so those apps get the usual "Your version of SQLite is too old" at connect instead of a confusing error later. That is safe because they cannot work today anyway, and 3.37 came out in November 2021.
