# Decode and escape form components with cgi/escape

`Rack::Utils.unescape` and `Rack::QueryParser#unescape` decode the keys and values of query strings and form bodies and every cookie value, and `Rack::Utils.escape` escapes every `Set-Cookie` value. They call `URI.decode_www_form_component` and `URI.encode_www_form_component`, which copy the string and run a `gsub` with a Hash lookup for each escape. `cgi/escape` decodes and escapes the same way, in C on MRI, and ships with every Ruby Rack supports; Rack already requires it for `escape_html` on Ruby before 3.2.

The first commit decodes with `CGI.unescape`. It keeps URI's check for an invalid %-encoding and its message, so `InvalidParameterError` is raised as before. The second commit escapes with `CGI.escape`, which escapes `*` and leaves `~` alone where URI does the opposite, so the two are mapped back; `%2A` in its output can only come from a `*`, since a `%` becomes `%25`. String subclasses, other objects and strings in encodings that aren't ASCII-compatible still go through URI, except that a `BasicObject` URI could convert now raises `NoMethodError` at the `instance_of?` guard. The native CGI fast paths bypass singleton overrides of String methods that URI calls, and the CGI escape fast path does not copy the input String's instance variables.

In Rails, cookies are read and written through these methods and form bodies are parsed by Rack. In whole requests of two open-source Rails apps with YJIT, this removes 3% to 10% of the instructions per request, mostly from the session cookie.
