# Look up indexes inline in LazyIndexedAttributeSet#[] and #keys

Since #59141, `LazyIndexedAttributeSet#[]` and `#keys` find each attribute through `index_for_name` and `lookup`, which are two method calls per attribute. Saving a record runs both for every attribute: dirty tracking calls `#keys` three times, and `#[]` once for each attribute it checks. So `update!` of one column costs more the wider the table is. This change inlines the two lookups in both methods, as `#fetch_value_at` and `#value_at` already do. The inlined code reads the same instance variables at the same points, so the results don't change.

Callgrind instructions per call, Ruby 4.0.9, no JIT, objects per call unchanged:

| | main | this change |
|---|---:|---:|
| `update!` of one column, 30 columns | 1,592,676 | 1,532,415 |
| `update!` of one column, 300 columns | 7,907,560 | 7,355,942 |
| load a record, then `changed?`, 30 columns | 466,230 | 436,644 |
| `serializable_hash`, 30 columns | 268,101 | 256,195 |

A second checkout of this change moved by at most 0.25% in these rows. With YJIT, load then `changed?` at 30 columns is 3.3% faster (a second checkout within 0.73%).
