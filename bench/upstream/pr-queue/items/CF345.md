# Migrate caching from Redis to Solid Cache

## Summary

Move production `Rails.cache` from Redis to Solid Cache in a dedicated SQLite database at `storage/db/production_cache.sqlite3`. Normal `db:prepare` creates the database and loads the checked-in schema; existing cache entries are intentionally not migrated.

- Solid Cache 1.0.10 with a 256 MiB `max_size` estimated eviction target and 30-day max age. This follows Solid Cache's installer default; it is not a hard cap on SQLite or WAL file size.
- Cache storage is isolated from primary, queue, and Cable databases and retains SQLite's normal WAL auto-checkpointing. The performance-load environment also has its own cache DB.
- Redis remains required for Action Cable until [#347](https://github.com/basecamp/once-campfire/pull/347) merges.
- The bounded per-worker response and fragment caches remain in memory and are unchanged. This is an operational cache-store migration; it makes no HTTP performance claim.

## Upgrade, backup, and rollback

Deploy normally; the cache starts cold and repopulates on demand. The cache database is disposable and is omitted from backups. Restore removes stale cache database files and sidecars before startup recreates the cache database. Rolling back to a Redis-cache release does not require a database rollback.
