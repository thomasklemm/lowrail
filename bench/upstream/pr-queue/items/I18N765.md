# Build the fallback options without a keyword Hash

### Summary

`Backend::Fallbacks#translate` copies the options for the fallback lookups with `options.merge(:fallback_in_progress => true, fallback_original_locale: locale)`. The two keywords are collected into a Hash first, so every translation through Fallbacks allocates two Hashes here.

This copies the options with `options.dup` and stores the two keys instead, avoiding the temporary keyword Hash without changing the caller's options. For ordinary Hashes the copy retains the default, `compare_by_identity` and key order.

Custom options-Hash `merge`, duplication or `[]=` hooks can behave differently on direct backend calls; `I18n.t` passes a fresh plain Hash without those hooks.

### Benchmark

Ruby 4.0.7, objects allocated per call with `I18n::Backend::Fallbacks` included (original measurements, same with and without YJIT; reproduced without YJIT for the simplified path):

```
                                 before   after
I18n.t(:hello)                     13  ->  12
I18n.t(:greet, name:)              21  ->  20
I18n.l(time)                       52  ->  49
```

The original guarded version counted 51,794 interpreter instructions per `I18n.t(:hello)` against 53,811 on master, 3.7% fewer; two runs of master differed by less than 0.4%. Across 10 open-source Rails apps (111 request, job and mailer workloads), that version removed 0.38% of all allocated objects, and all ten allocated fewer objects. Those instruction and app measurements have not been rerun for the simplified path.

### Testing

Added a test that the fallback lookups receive the options with both keys, in the same order, without changing the caller's options. The test suite passes (1,608 runs, 2,680 assertions). The retained test also passes on master; independent mutation checks reject reusing the caller's Hash, omitting the progress flag or storing the wrong original locale.
