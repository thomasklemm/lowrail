# Require minitest 5.18 in Active Support

Declare `minitest >= 5.18`, the first release with `refute_pattern`. Since 23420be739 added the unconditional `assert_not_pattern` alias, Bundler can select an older minitest that satisfies the declared `>= 5.1` requirement but fails to load `ActiveSupport::TestCase`:

```
undefined method 'refute_pattern' for class 'ActiveSupport::TestCase' (NameError)
```

active_model_serializers 0.10.16's suite hits this: its [development dependency](https://github.com/rails-api/active_model_serializers/blob/6934c8bd31f4025fe7548a07d50a82f18df8e689/active_model_serializers.gemspec#L42), unchanged on `0-10-stable`, is:

```ruby
  spec.add_development_dependency 'minitest', ['~> 5.0', '< 5.11']
```

Load-only checks on Ruby 3.3.13:

| `require "active_support/test_case"` | minitest 5.10.3 | minitest 5.18.0 |
|---|---|---|
| 8.1.4.1 | loads | loads |
| `1e235cee11` | NameError | loads |
| `1e235cee11` without the alias | loads | loads |

With this floor, Bundler reports a conflict for incompatible pins such as AMS's `< 5.11`; other applications can resolve a newer minitest. The matching lockfile requirement changes too; its locked minitest stays on 6. On Ruby 4, resolution must select a later Ruby-compatible release because minitest 5.18.0 declares Ruby < 4.0.
