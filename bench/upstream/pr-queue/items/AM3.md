# Stop setting the Action Mailer delivery job in `load_defaults`

Since #59820 Action Mailer no longer depends on Active Job, and its `delivery_job` reader falls back to `ActionMailer::MailDeliveryJob` on its own. But `load_defaults "6.0"` and later still set `config.action_mailer.delivery_job = "ActionMailer::MailDeliveryJob"`, and the railtie constantizes it when Action Mailer loads. That file requires Active Job, so an app whose Gemfile lists the Rails components with `actionmailer` and without `activejob` raises `LoadError: cannot load such file -- active_job` when a mailer loads, including at boot with eager loading, as I found booting [Discourse](https://github.com/discourse/discourse/blob/d57bed343995d40d7cbe917f5e10b9e695a579fb/Gemfile#L11-L17) on main, even though it never needs Active Job to load a mailer.

This removes the redundant default, so the delivery job, and Active Job with it, is only loaded when something uses it. Apps that bundle Active Job get the same `MailDeliveryJob` as before.
