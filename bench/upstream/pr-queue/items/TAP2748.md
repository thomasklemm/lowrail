# Avoid loading unused ActiveSupport::Configurable during reflection

### Motivation

On Rails 8.1, generating gem RBIs can emit `ActiveSupport::Configurable is deprecated without replacement, and will be removed in Rails 8.2` even when the application never uses that API. With deprecations configured to raise, generation fails instead.

Rails deliberately removed Configurable from its eager autoloads in https://github.com/rails/rails/pull/55943: its plain autoload must remain available, but loading the file emits the deprecation. Tapioca's autoload tracker currently forces it anyway. This is a different mechanism from the deprecated constant proxies addressed in #2701.

### Implementation

`Runtime::Reflection.constantize` leaves the Rails 8.1+ Configurable autoload pending when asked for it or a constant under it, unless the application already loaded it. The check sits in the shared lookup rather than in the autoload tracker, because the gem pipeline resolves symbols and subconstants through the same helper. Other autoloads load normally, explicit usage still emits the Rails deprecation and generates Configurable RBIs, and Rails 8.0 is unchanged.

### Tests

Added a CLI test that generates Active Support RBIs with deprecations set to raise and leaves the Configurable autoload unchanged (it fails without the fix), and a control showing that explicit Configurable usage still warns and gets its RBI. A maintainer will need to add the `bugfix` release label.
