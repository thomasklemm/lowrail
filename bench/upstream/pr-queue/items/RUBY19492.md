# YJIT: Count dynamic sends before dispatch

`--yjit-stats` counts too few dynamic sends. When the callee raises, `throw`s, or is left through a block `break`, the send isn't counted in `num_send_dynamic`, although the `send_*` fallback counters count it. `gen_send_dynamic` emits the `num_send_dynamic` increment after the VM call that `vm_sendish` emits, and in those cases that code never runs. The fallback counters are incremented before the call.

This PR moves the increment before `vm_sendish`, right after `jit_prepare_non_leaf_call` saves PC and SP. The call itself and the stack handling around it are unchanged. `gen_counter_incr` only emits code when stats are enabled, so code generated without `--yjit-stats` is identical.

With `--yjit-stats`, per measured iteration of sequel, `num_send_dynamic` goes from 25,000 on master to 26,000 with this PR, while `num_send` (264,129) and `send_singleton_class` (11,000) don't change. The extra 1,000 come from the nonlocal `return` in the block that Sequel's `primary_key_lookup` passes to `fetch_rows`.
