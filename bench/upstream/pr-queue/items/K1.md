# Stop merging type keys and built names into LazyIndexedAttributeSet#keys

In #59141, `LazyIndexedAttributeSet#row_keys` became every name in the set's indexes, which already cover every typed attribute of the model. So `row_keys | @ctx.type_keys | cached_names` in `#keys` always equals `row_keys`, but still builds three more arrays and walks the indexes again. Dirty tracking and `attribute_names` call `#keys` on every `changed?`, `save`, `inspect` and `serializable_hash`. `materialize`, which `save` and `dup` run, likewise walked the type keys a second time.

This drops the unions and the second walk, and with them the context's unused `type_keys`. `#keys` returns the same names in the same order, as `#to_hash` already assumes.

Callgrind instructions and objects per call, Ruby 4.0.9, no JIT, a 30-column record:

| | main | this change |
|---|---:|---:|
| `changed?` | 263,682 (6 objects) | 167,106 (1) |
| `serializable_hash` | 276,346 (38) | 179,170 (33) |
| `update!` of one column | 1,588,221 (201) | 1,299,388 (186) |
| `find` then `save` | 1,728,884 (179) | 1,402,556 (164) |
| `find` then `dup` | 1,120,187 (183) | 1,064,920 (183) |

A second checkout of main moved by at most 0.27%. With ZJIT on Ruby master 9aa0898240: `changed?` −51%, `serializable_hash` −37%, `update!` −26%, `find` then `save` −27% (a second checkout of main within 0.19%).
