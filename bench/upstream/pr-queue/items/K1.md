# Stop merging type keys and built names into LazyIndexedAttributeSet#keys

In #59141, `LazyIndexedAttributeSet#row_keys` became every name in the set's indexes, which already cover every typed attribute of the model. So `row_keys | @ctx.type_keys | cached_names` in `#keys` always equals `row_keys`, but still builds two more arrays and walks the indexes again. Dirty tracking and `attribute_names` call `#keys` on every `changed?`, `save`, `inspect` and `serializable_hash`. `materialize`, which `save` and `dup` run, likewise walked the type keys a second time.

This drops the unions and the second walk, and with them the context's unused `type_keys`. `#keys` returns the same names in the same order, as `#to_hash` already assumes.
