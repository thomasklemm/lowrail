# Skip the String comparison when a fallback hits the requested locale

`Backend::Fallbacks#translate` calls `on_fallback` only when the translation came from a different locale, and checks that with `locale.to_s != fallback.to_s`. Most lookups hit the first fallback, which is the requested locale itself, so every such translation converts both Symbols to new Strings just to find they are equal.

This compares the two locales directly first, which settles it for Symbol locales, and keeps the String comparison for everything else, so a String and a Symbol for the same locale still count as the same locale.

Objects allocated per call with `I18n::Backend::Fallbacks` included, Ruby 4.0 (same with and without YJIT):

| Call | Before | After |
| --- | ---: | ---: |
| `I18n.t(:hello)` | 13 | 11 |
| `I18n.t(:greet, name:)` | 21 | 19 |
| `human_attribute_name` (hit) | 21 | 19 |

Across 20 open-source Rails apps (251 request, job and mailer workloads), this removes 0.4% of all allocated objects, most of it in one translation-heavy dashboard; 14 of the apps translate through this path.
